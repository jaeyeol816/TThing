# SDK v3.2 인증 설계

## 1. 범위

Nova 게이트웨이를 경유하는 SDK 클라이언트의 인증·토큰 수명 관리를 다룬다.
프로젝트 코드명 atlas-auth. 관련 저장소: sdk-core.

## 2. 토큰 모델

### 2.1 발급

클라이언트는 최초 1회 사용자 자격증명으로 인증하고 access token 을 받는다.
토큰은 JWT 이며 서명은 RS256 을 쓴다.

### 2.2 수명

**토큰 수명은 24시간이다.**

이 값은 v2.x 의 4시간에서 늘어난 것이다. 배경은 `notes/2025-11-auth.md` 참조.
요약하면 모바일 클라이언트의 재인증 빈도가 사용자 이탈로 이어진다는
데이터가 있었고, 백그라운드 갱신으로 해결하기로 했다.

### 2.3 갱신 — 백그라운드 무음 갱신

토큰 만료 2시간 전부터 클라이언트 SDK 가 **백그라운드에서 무음으로 갱신**한다.
사용자 상호작용이 필요 없다.

```
if now > issued_at + 22h:
    renew_silently()          # 사용자에게 알리지 않는다
```

갱신은 **세션 상태를 확인하지 않는다.** 토큰 자체의 유효성만 본다.

### 2.4 세션 바인딩 — 적용하지 않음

**현행 v3.2 는 세션 바인딩을 쓰지 않는다.**

토큰은 발급 이후 어떤 세션 컨텍스트와도 결합되지 않으며, 유효 기간 내에는
어느 세션에서든 사용할 수 있다. 이 결정의 배경은 두 문서에 나뉘어 기록돼 있다:

- `notes/2025-11-auth.md` (김철수, 개인 메모)
- `choi/docs/auth-review.md` (최민수, 설계 리뷰)

두 기록의 서술이 다르다. 둘 다 사실일 수 있다.

## 3. 구현 위치

| 관심사 | 모듈 |
|---|---|
| 토큰 발급·검증 | `sdk-core/src/auth/token.py` |
| 백그라운드 갱신 | `sdk-core/src/auth/renewal.py` |
| 게이트웨이 어댑터 | `sdk-core/src/gateway/nova.py` |

## 4. 알려진 제약

- 토큰 무효화(revocation) 경로가 없다. 만료를 기다려야 한다
- 세션 종료와 토큰 수명이 독립적이다
- 레거시 SSO 경유 시 클레임 매핑이 부분적으로만 동작한다

## 5. v3.3 검토 항목

- 토큰 무효화 API 추가
- 세션 바인딩 옵션 제공 (기본 off)
- 갱신 시 세션 유효성 재확인 훅
