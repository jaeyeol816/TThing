# SDK v3.2 인증 설계 리뷰

**리뷰어**: 최민수 선임
**대상**: SDK v3.2 인증 설계 (설계자 김철수 책임)
**일자**: 2025-12-03
**결과**: 조건부 승인

---

## 1. 리뷰 범위

토큰 수명 정책, 갱신 방식, 세션 바인딩 적용 여부.

## 2. 주요 결정 사항

### 2.1 세션 바인딩 미적용 — 승인

**세션 바인딩 미적용 결정. 레거시 SSO 게이트웨이가 세션 식별자를
downstream 으로 전파하지 않아 바인딩 자체가 불가능했다.**

확인 경로:

1. 레거시 SSO 게이트웨이의 클레임 매핑 설정을 확인했다.
   세션 식별자에 해당하는 클레임이 매핑 테이블에 없다.
2. 게이트웨이 벤더 문서를 확인했다. 해당 버전은 세션 식별자 전파를
   지원하지 않는다. 상위 버전에서 추가됐으나 업그레이드 경로가 막혀 있다.
   (인증서 체인 호환성 문제)
3. Nova 게이트웨이 쪽은 전파가 되지만, 레거시 SSO 를 경유하는 트래픽이
   전체의 40% 라 부분 적용은 의미가 없다고 판단했다.

즉 **바인딩을 하고 싶어도 할 수 없는 상태**였다. 설계 선택이 아니라 제약이다.

> 성능 쪽 이슈도 별도로 보고됐다고 들었으나 이 리뷰에서 직접 확인하지는
> 않았다. 어느 쪽이든 결론은 같다.

### 2.2 토큰 수명 24시간 — 조건부 승인

무효화 경로 없이 24시간은 길다. 아래를 조건으로 승인한다.

- v3.3 에 토큰 무효화 API 추가
- 무효화 API 추가 전까지 고위험 작업에는 재인증 요구

### 2.3 백그라운드 무음 갱신 — 승인

갱신 시 세션 유효성을 확인하지 않는 점을 지적했으나,
현재 세션 식별자 전파가 안 되므로 확인할 대상 자체가 없다.
2.1 이 해결되면 함께 재검토한다.

## 3. 미해결 지적 사항

| # | 지적 | 상태 |
|---|---|---|
| 1 | 토큰 무효화 경로 부재 | v3.3 이월 |
| 2 | 세션 종료와 토큰 수명이 독립 | 2.1 해결 후 재검토 |
| 3 | 레거시 SSO 클레임 매핑 부분 동작 | 벤더 문의 중 |

## 4. 후속

- 레거시 SSO 게이트웨이 업그레이드 가능성 재조사 (담당: 최민수)
- 무효화 API 설계 (담당: 김철수, v3.3)
