## 2. 설치

```bash
git clone <저장소>
cd prompthon

make setup          # uv sync + .env 생성 + 데이터 디렉터리
```

`make setup` 이 `.env.example` 을 복사해 `.env` 를 만든다. 사외 모델을 쓸 거면 채운다.

```bash
# .env
FRIENDLI_TOKEN=flp_...
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_SESSION_TOKEN=...            # 임시 자격증명이면
AWS_REGION=us-east-1
```

### 환경 검증

```bash
set -a; . ./.env; set +a
make preflight
```

27개 항목을 검사하고 **사람이 읽을 진단**을 출력한다. 실패 항목마다 무엇을 고쳐야
하는지 적혀 있다. 검사 범위:

- 런타임 버전 · `.gitignore` 가 자격증명을 커버하는지
- 필수 데이터 파일 · 코퍼스 · 세션 정합성
- 신뢰 경계 설정값
- EXAONE 실제 연결 (1회 핑)
- Bedrock 실제 연결 (1회 핑)
- CDK 도구 (배포할 때만)

> `실패 0` 이면 진행한다. 경고는 대개 "사외 SaaS 를 쓰고 있다" 같은 **의도된** 것이다.

## 3. 실행 — 세 가지 방법

### 3.1 데스크톱 앱 (권장)

```bash
make app
```

한 번에 다 한다.

1. `npm install` — Tauri CLI 를 내려받는다 (첫 실행만)
2. Rust 빌드 — 첫 실행은 2분쯤 걸린다
3. 백엔드를 스스로 띄운다 (이미 떠 있으면 그 서버에 붙는다)
4. 준비되면 창을 만든다

창을 닫으면 백엔드도 함께 종료된다.

> 첫 빌드가 오래 걸린다. 진행 상황은 터미널에 나온다.
> 백엔드 로그도 `[backend:out]` 접두사로 함께 흐른다 — 조용히 실패하지 않는다.

배포용 `.app` / `.dmg` 를 만들려면:

```bash
make app-build      # app/src-tauri/target/release/bundle/ 에 생긴다
```

### 3.2 브라우저

```bash
make run            # http://127.0.0.1:8080
```

Tauri 창이 여는 것과 **완전히 같은 화면**이다. 데스크톱 셸은 창을 만드는 일만 한다.

> `127.0.0.1` 고정이다. 재수화된 실제 이름이 지나가는 표면이므로 네트워크에 노출하지
> 않는다. 굳이 열려면 `MESH_ALLOW_NETWORK_BIND=1` 을 명시해야 한다.

### 3.3 오프라인 — 네트워크 0회

```bash
EXAONE_MODE=mock AGENT_TRANSPORT=mock make run
```

녹화된 픽스처로 전 시나리오가 돈다. 발표장 와이파이를 믿지 않아도 된다.

**화면 헤더에 목업 모드가 표시된다** — 심사자를 속이지 않는다.
목업 모드에서도 등급 판정·화이트리스트 조립·검증 6단계·감사 로그는 **실제 코드가 돈다.**
대역은 LLM 응답만 흉내 낸다.

화면 없이 CLI 로 시연하려면:

```bash
EXAONE_MODE=mock AGENT_TRANSPORT=mock make demo
```

## 4. 화면 둘러보기

### 헤더 — 상시 표시

| 요소 | 뜻 |
|---|---|
| **신뢰 경계 시뮬레이션** 배지 | 누르면 무엇이 시뮬레이션인지 펼친다 |
| **EXAONE / Agent** 배지 | `live` 인지 `mock` 인지 |
| **보는 사람** 드롭다운 | 관점 전환. **인증이 아니다** — 화면이 그렇게 적어 둔다 |

### 탭 4개

| 탭 | 하는 일 |
|---|---|
| **질문하기** | 지목 → 질문 → 미리보기 → 전송 → 답변 |
| **내 문서** | 문서 업로드 → 등급 + 근거 확인 → 목록 관리 |
| **인박스** | 확인 요청 처리 (승인 / 수정 / 직접 답변) |
| **감사 로그** | 경계를 넘은 것 전부 + 원문 검색 |

## 5. 실사례 — 내 기밀 문서를 올리고 남이 질문한다

이게 이 도구의 실사용 형태다. 순서대로 따라가면 5분이면 끝난다.

### 5.1 기밀 문서를 만든다

아무 텍스트 편집기로 파일을 하나 만든다. 이름은 `재계약-메모.md`.

```markdown
# title: 재계약 협상 메모
# as_of: 2026-08-19

고객사 H 는 요구사항 REQ-4412 에서 30분 주기 재인증을 강제한다.
재계약 총액은 37억 원 규모이고 납기는 2027-03-15 이다.
위약금 조항이 붙어 있어 일정 협상 여지가 없다.
우리 SDK 는 무상태 토큰 갱신을 쓰므로 이 제약과 정면으로 충돌한다.
```

> 여기 적은 **고객사 H · REQ-4412 · 37억 원 · 2027-03-15** 를 기억해 두자.
> 마지막에 이 문구들로 감사 로그를 검색해 **0건**임을 확인할 것이다.

### 5.2 올린다

1. 헤더에서 **보는 사람**을 `김철수 책임` 으로 바꾼다
2. **내 문서** 탭으로 간다
3. 파일을 점선 영역에 **끌어다 놓는다** (또는 클릭해서 선택)

파일이 없어도 된다. **또는 붙여넣기로 만들기** 를 펼쳐 파일명과 내용을 직접 적어도 같다.

### 5.3 올리는 즉시 등급이 나온다

```
기밀로 판정됐습니다
  근거  금칙어 '고객사 H'
  근거  금칙어 패턴 /\d+\s*억\s*원?/
  → 이 문서를 쓰는 질문은 원문 대신 구조 요약만 경계를 넘습니다
```

**근거가 함께 나오는 것이 중요하다.** 등급 판정이 블랙박스가 아니고, 나중에 답이
무뎌졌을 때 "왜?"를 되짚을 수 있다.

문서는 `질의 후보` 로 표시된다. 후보인 문서만 질문에 동원된다.

> 확인해 볼 것: 문서 맨 위에 `# 보안 등급: 공개` 를 적고 다시 올려 보자.
> **여전히 기밀이다.** 금칙어 검사가 자기신고보다 앞선다 — 헤더 한 줄로 게이트키퍼를
> 우회할 수 있으면 안 되기 때문이다.

### 5.4 다른 사람이 질문한다

1. 헤더에서 **보는 사람**을 `박선영 선임` 으로 바꾼다
2. **질문하기** 탭으로 간다
3. `김철수 책임` 카드를 클릭해 지목한다 (최대 2명)
4. 질문을 적는다

```
고객사 요구사항과 우리 SDK 토큰 갱신 방식이 충돌하나요?
```

5. **[미리보기 만들기]** 를 누른다

> 이 순간 **김철수 책임에게는 아무 알림도 가지 않는다.** 인박스도 비어 있고 감사
> 레코드도 없다. 취소하면 흔적이 남지 않는다.

### 5.5 결정적 장면 ① — 나갈 내용 전문

모달이 열린다.

```
이 내용이 경계를 넘습니다
  대상   김철수 책임의 Agent  [기밀]
  검증   6/6
  크기   727 bytes
  원문 문장 수   0  (측정값)
```

**검증 6단계**가 모두 통과로 표시되고, 그 아래에 **보내는 내용 전문**이 있다.
접기도 생략도 "더 보기" 도 없다.

```json
{
  "task": "constraint_conflict_check",
  "domain": "authentication",
  "entities": [
    { "ref": "REQ_A", "role": "external_requirement" },
    { "ref": "COMP_A", "role": "our_component" }
  ],
  "facts": {
    "REQ_A": {
      "session_binding": "required",
      "max_session_hours": 8,
      "renewal_mode": "explicit",
      "credential_reuse_allowed": false
    },
    "COMP_A": {
      "session_binding": "none",
      "credential_lifetime_hours": 24,
      "renewal_mode": "background_silent"
    }
  },
  "answer_format": { "conflict": "bool", "reason": "string", "mitigations": "string[]" }
}
```

**직접 읽어 보자.** 고객사명도, 37억 원도, REQ-4412 도, 2027-03-15 도, 원문 문장도 없다.
남은 것은 문제의 *구조*다 — 한쪽은 세션 바인딩을 요구하고 한쪽은 안 쓴다는 사실.

맨 아래 **포함되지 않은 것** 목록이 있다.

> ⚠️ 이 목록은 **표현에 따라 다르다.** 기밀(구조 추출)은 8개 범주 전부를 약속하지만,
> 사내(가명화)는 원문 문장을 유지하는 것이 등급의 정의이므로 그것을 약속하지 않는다.
> 화면이 약속하는 것과 페이로드에 있는 것이 어긋나면, 그건 유출보다 나쁘다 —
> 사용자가 거짓 근거로 [전송] 을 누르게 된다.

### 5.6 전송하고 답을 받는다

**[이대로 전송]** 을 누른다.

```
김철수 책임의 Agent          신뢰도 0.85  (live)   사외 Agent 사용
  충돌 여부: 예
  이유: 고객사 H 5G 코어망 인증 요구사항명세서는 session_binding=required 와
        max_session_hours=8 을 요구하지만, SDK 인증 설계 문서는 …
  대응 방안:
    - 세션 바인딩 레이어 추가 …
    - 세션 수명 정책 조정 …

  근거: 고객사 H 5G 코어망 인증 요구사항명세서  [기밀 · 2026-07-15 · 공식]
  근거: SDK 인증 설계 문서 v3.2               [사내 · 2026-08-19 · 공식]
```

**답변에는 실제 이름이 나온다.** 이게 정상이다.

사외 Agent 는 `REQ_A` 로 답했고, **사내망 안에서 재수화**해 실제 제목으로 되돌린
것이다. 되돌리지 않으면 사람이 읽을 수 없는 답이 된다.

정리하면:

| 어디 | 실제 이름 | 왜 |
|---|---|---|
| 경계를 넘는 페이로드 | **없다** | 사외 모델이 봐서는 안 된다 |
| 감사 로그 (페이로드 사본) | **없다** | 같은 것의 사본이다 |
| 사용자에게 보이는 답변 | **있다** | 신뢰 구역 안이고, 없으면 쓸모없다 |

**김철수 책임은 여전히 방해받지 않았다.** 인박스가 비어 있다.

### 5.7 되돌리기

**내 문서** 탭에서 올린 문서의 **[삭제]** 를 누르면 파일이 지워지고 질의 후보에서도 빠진다.

> 원래 있던 샘플 문서(`원래 있던 것` 표시)는 지울 수 없다. 데모가 깨지기 때문이다.

### 5.8 터미널로 같은 걸 확인하려면

```bash
make run                        # 다른 터미널에서 live 로 띄워 두고
make e2e                        # 업로드 → 질문 → 유출 검사 → 정리
make e2e ARGS=--show-payload    # 나갈 페이로드 전문까지 출력
```

실제 HTTP 로 붙어 화면이 하는 것과 같은 순서로 호출하고, 페이로드와 감사 로그에서
원문 조각을 찾는다. 7단계를 거쳐 마지막에 `종단 실측 통과` 가 나오면 끝이다.

```
── ③ 유출 검사 — 경계를 넘는 페이로드를 본다
  · person:kim: secret/structured · 검증 6/6 · 원문 문장 0개 · 727B
    ✓ ngram    원문 5-gram 0건 (대조 785개)
  ✓ 원문 0개 — 경계를 넘는 것에 기밀 조각이 없다
── ⑥ 감사 로그 — 원문 문구로 검색하면 0건
  ✓ '고객사 H' → 0건
  ✓ 'REQ-4412' → 0건
  · 'session_binding' → 7건  ← 구조는 나갔다
```

> ⚠️ **`make e2e` 는 live 모드가 필요하다.** 매번 새 문서를 만들어 올리므로 목업
> 픽스처가 있을 수 없다. 목업 모드로 띄워 두면 스크립트가 `/api/health` 로 확인하고
> 즉시 멈춘다 — 한참 진행한 뒤 알 수 없는 400 을 보는 것보다 낫다.
>
> 네트워크 없이 같은 흐름을 보려면 `make eval` 을 쓴다. 같은 종단 시나리오를 대역으로
> 고정한 테스트다.

## 6. 인박스 — 확인 요청 처리

Agent 가 확신을 갖지 못하면(신뢰도 0.75 미만) 담당자에게 확인 요청이 간다.

**보는 사람**을 담당자로 바꾸고 **인박스** 탭으로 가면 이렇게 온다.

- **요약** — 누가 무엇을 물었나
- **지금까지 찾은 근거** — Agent 가 참조한 것
- **답변 초안** — 손보기만 하면 되는 상태
- **이미 답변된 것** — 같은 질문에 과거에 답한 내역

버튼 3개.

| 버튼 | 결과 |
|---|---|
| **승인** | 초안을 그대로 보낸다. 승인된 Q&A 로 쌓여 다음 질문에 재사용된다 |
| **수정 후 승인** | 한 번 누르면 편집창이 열리고, 고친 뒤 다시 누르면 보낸다 |
| **내가 아님** | 옆 드롭다운에서 담당자를 골라 넘긴다 |

> **[내가 아님]** 은 드롭다운을 먼저 골라야 동작한다. 시스템이 자동으로 다시 묻지
> 않는다 — 질문자가 직접 다시 물어야 한다. 자동 재질의를 넣으면 넘기기만 반복되는
> 고리가 생긴다.

> 목표는 "확인 요청을 없애는 것"이 아니라 **몇 초 안에 끝나게 하는 것**이다.
> 요약·근거·초안이 함께 오는 이유다.

## 7. 감사 로그 — 0건을 직접 확인

**감사 로그** 탭. 경계를 넘은 것이 전부 여기 있다.

### 결정적 장면 ②

검색창에 §5.1 에서 기억해 둔 문구를 넣는다.

```
REQ-4412        →  0건 — 이 문구는 경계를 넘은 적이 없습니다
37억            →  0건
고객사 H         →  0건
2027-03-15      →  0건
```

빠른 검색 배지(`REQ-4412` `EAP-AKA` `H社` `12억원` `session_binding`)를 눌러도 같다.

마지막 하나가 재미있다.

```
session_binding →  N건
```

**구조화된 값은 나갔고 원문은 나가지 않았다.** 이게 이 프로젝트의 주장 전체다.

### 레코드에 무엇이 있나

각 레코드는 페이로드 **전문**과 함께 보관된다.

| 필드 | 왜 |
|---|---|
| 도착지 URL | 원문이 어디로 갔는지가 로그로 증명된다 |
| 등급 · 표현 | 어떤 형태로 나갔나 |
| 검증 요약 | 6/6 이었나 |
| SHA-256 | 페이로드가 바뀌지 않았음 |
| 승인자 | 누가 [전송] 을 눌렀나 |

> **신뢰 구역 안에서 처리된 질의는 이 목록에 없다.** 섞으면 "레코드가 없다"가 증거로
> 쓰이지 못한다. 차단된 질문은 감사 로그에 남지 않는다 — 나간 적이 없으니까.

### 전수 확인

```bash
make eval-dump-payloads
```

경계를 넘은 것 **전부**를 `aidlc-docs/construction/g4-payload-dump.md` 로 덤프한다.
페이로드 1건 = 섹션 1개, 전문이 절단 없이 들어가고, 각 섹션에 확인 체크박스가 있다.

자동 검사는 원문 5-gram 과 금칙어를 기계적으로 대조한다. 하지만 **아는 것만** 잡는다.
목록에 없는 새 고객사명, 의미만 옮긴 서술, 슬롯 이름 자체가 정보인 경우, 값 조합으로
대상이 특정되는 경우 — 이건 사람이 읽어야 보인다. 그래서 덤프가 있다.

## 9. 문제 해결

### `make app` 이 "저장소 루트를 찾지 못했습니다"

Tauri 가 `Makefile` 과 `src/mesh` 가 함께 있는 디렉터리를 위로 훑어 찾는다.
못 찾으면 직접 알려준다.

```bash
MESH_BACKEND_CWD=/절대/경로/prompthon make app
```

### `make app` 이 "백엔드가 120초 안에 응답하지 않았습니다"

백엔드 자체가 뜨지 않는다. 따로 띄워 원인을 본다.

```bash
make run          # 오류 메시지를 읽는다
make preflight    # 환경 문제인지 확인
```

이미 다른 프로세스가 8080 을 쓰고 있으면 Tauri 는 **그 서버에 붙는다** (정상 동작).

### `FixtureMissing: 픽스처가 없다`

목업 모드에서 프롬프트에 들어가는 내용이 바뀌면 픽스처 키가 바뀐다. 그게 설계다 —
키가 내용에 묶여 있지 않으면 목업이 실물과 다른 것을 재생하고 알 방법이 없다.

```bash
make record-fixtures          # 시연 3막
make record-dump-fixtures     # G4 덤프 경로 (업로드 포함)
```

둘 다 `live` 로 돌며 녹화한다 — 자격증명이 필요하다.

### 답변이 "이 질문에 해당하는 task 가 어휘 사전에 없다"

의도한 동작이다. 어휘 사전에 그 질문에 맞는 구조가 없으면 **보내지 않고** 신뢰 구역
안에서 답한다. 감사 로그에 레코드가 남지 않는다.

기본 스키마로 대충 보내면 *묻지 않은 것에 자신 있게 답하는* 일이 생긴다. 실측에서
`"그때 p99 지연이 얼마였나요?"` 에 인증 방식 충돌을 신뢰도 0.75 로 답했다.
유출은 아니지만 사용자가 그 답을 믿는다 — 폴백보다 나쁘다.

프리셋 질문(1~3막)은 어휘 사전에 맞춰져 있다. 자유 질문은 `충돌` `기법` `이유` 같은
말이 들어가면 맞는 스키마를 찾는다.

### 업로드가 422 로 거부된다

응답의 `detail` 에 어느 필드가 왜 틀렸는지 나온다.

| 사유 | 고치는 법 |
|---|---|
| 확장자 | 텍스트만 받는다 — `.md .txt .py .yaml .yml .json .log .csv .sql .sh .toml .ini .cfg` |
| 경로 구분자 · `..` · 숨김 파일 | 파일명에서 뺀다 |
| 길이 | 파일명 120자, 내용 200,000자 |

> 오류 응답은 **보낸 값을 되비추지 않는다.** 기밀 문서가 상한을 넘겼을 때 오류 메시지에
> 전문이 실리면, 그 원문이 로그·프록시·브라우저 히스토리로 퍼진다.

### 업로드가 400 `UploadRejected`

`config/agents.yaml` 에 없는 사람으로 올리려 했거나 내용이 비었다.

### 세션 파일이 지저분해졌다

데모를 돌리면 `data/sessions/*.json` 과 `data/corpus/*/uploads/` 가 바뀐다.
업로드 디렉터리는 `.gitignore` 에 있고, 세션 파일은 이렇게 되돌린다.

```bash
git checkout data/sessions/
rm -rf data/corpus/*/uploads/
```

### 감사 DB 를 비우고 싶다

```bash
rm -f data/mesh.db*
```

또는 덤프를 새로 만들 때 `make eval-dump-payloads` 가 `--fresh` 로 지우고 시작한다.

## 10. 다른 컴퓨터로 옮기기

이 프로젝트는 처음부터 이식성을 요건으로 잡았다.

| 규칙 | 왜 |
|---|---|
| 절대 경로를 **저장하지 않는다** | `MESH_DATA_ROOT` 상대 경로만. 절대 경로는 저장 시점에 거부된다 |
| 잠금 파일을 커밋한다 | `uv.lock` · `package-lock.json` · `Cargo.lock` |
| 데이터가 저장소 안에 있다 | 코퍼스·세션·픽스처 전부 |
| 외부 CDN 참조 0건 | 화면이 오프라인에서 뜬다 |
| 목업 모드가 완전하다 | 자격증명 없이 전 시나리오 |

옮긴 컴퓨터에서:

```bash
make setup
make preflight                                        # 여기서 문제가 드러난다
EXAONE_MODE=mock AGENT_TRANSPORT=mock make run        # 자격증명 없이 확인
```

`make preflight` 가 `MESH_DATA_ROOT 가 절대 경로다` 라고 경고하면, `.env` 에서
`MESH_DATA_ROOT=./data` 로 바꾼다.

## 마지막으로 — 이 도구가 하지 않는 것

솔직하게 적어 둔다. 데모 중에 지적당하는 것보다 먼저 밝히는 게 낫다.

| 없는 것 | 지금 상태 |
|---|---|
| **사용자 인증** | 드롭다운 전환은 관점 전환이다. 화면이 그렇게 적어 둔다 |
| **원본 시스템 권한 승계** | 실배포 최우선 요건. 없으면 권한 우회 도구가 된다 |
| **사내망 EXAONE** | 지금은 사외 SaaS. 설정값 하나로 전환되고 화면이 상시 표시한다 |
| **바이너리 문서** | 텍스트로 읽히는 것만. 좁힌 범위다 |

세 번째가 가장 중요하다. 이 아키텍처가 보장하는 것은 **"원문이 엔드포인트 하나에만
전달된다"** 이고, 그 엔드포인트를 사내로 옮기는 것은 `TRUSTED_ZONE_LLM_BASE_URL` 을
바꾸는 일이다. 감사 로그가 매 질의마다 그 값을 기록하므로 **거짓말을 할 수 없다.**
