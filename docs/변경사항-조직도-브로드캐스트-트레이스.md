# 변경사항 — 조직도 · 브로드캐스트 · 처리 경과

> 이 문서는 세 가지 변경을 다룬다.
>
> 1. **조직도** — 본부 → 센터/연구소 → 팀 → 사람. 10명이 각자 폴더와 Agent 를 갖는다
> 2. **브로드캐스트** — 사람을 먼저 고르지 않는다. 질문을 뿌리고 답할 수 있는 사람이 남는다
> 3. **처리 경과** — "Gatekeeper: 통과" 한 줄을 6단계로 펼치고, 각 단계의 **실제 자료**를 연다
>
> 각 절은 *무엇을 바꿨나 → 왜 그렇게 했나 → 어디를 고치면 되나* 순서다.
> 확장 지점은 **⚙️** 로 표시했다.

---

## 0. 한눈에 — 바뀐 흐름

### 이전

```
사람이 조직도에서 담당자를 고른다  →  질문 입력  →  prepare  →  send  →  답변
        ↑
   "누가 이걸 아는가" 를 이미 알고 있어야 한다
```

### 이후

```
질문 입력
   │
   ├─ POST /api/ask/broadcast        전원의 Agent 에게 방송 (경계를 넘지 않는다)
   │     └─ 각자 "내가 답할 수 있는가" 판정
   │
   ├─ 조직도에 파동 → 관련 없는 사람은 흐려지고 답할 수 있는 사람만 남는다
   │
   ├─ 사람을 누른다                  ← 지목은 여전히 사람이 한다 (FR-29)
   │
   ├─ POST /api/ask/prepare          그 사람에게만. 게이트키퍼가 여기서부터 판정
   ├─ POST /api/ask/send
   │
   └─ 답변 말풍선 → "단계별로 보기" → GET /api/trace/{id}
                                       6단계 각각의 실제 자료
```

**지목이 사라진 것이 아니라 시점이 뒤로 갔다.** 후보가 좁혀진 뒤에 사람이 고른다.

### 새로 생긴 파일

| 파일 | 무엇 | 레이어 |
|---|---|---|
| `config/org.yaml` | 조직의 **자리** 정의 (본부·센터·팀) | 데이터 |
| `src/mesh/org.py` | 자리와 직급의 일반 트리. 층 이름을 모른다 | L0 |
| `src/mesh/triage.py` | 브로드캐스트 선별. 문서를 읽지 않는다 | L3 |
| `src/mesh/trace.py` | 처리 경과 기록. 원문을 담지 않는다 | L1 |
| `tests/unit/test_org.py` · `test_triage.py` · `test_trace.py` | 위 세 개의 성질을 고정 | — |
| `docs/변경사항-조직도-브로드캐스트-트레이스.md` | 이 문서 | — |

### 새로 생긴 API

| 엔드포인트 | 하는 일 | 경계를 넘는가 |
|---|---|---|
| `GET /api/org` | 조직도 트리 | ✗ |
| `POST /api/ask/broadcast` | 질문 방송 + 선별 | ✗ (타입으로 못 박음) |
| `GET /api/trace/{trace_id}` | 처리 경과 6단계 | ✗ (loopback 전용) |

## 1. 조직도

### 1.1 무엇을 바꿨나

`config/org.yaml` 이 조직의 **자리**를, `config/agents.yaml` 이 **사람**을 정의한다.

```yaml
# config/org.yaml — 자리
unit_kinds:                 # 층의 종류. 순서가 곧 기본 표시 순서
  - { id: division, label: 본부 }
  - { id: center,   label: 센터·연구소 }
  - { id: team,     label: 팀 }

ranks:                      # 직급. order 가 팀 안 정렬 기준 (작을수록 위)
  - { id: task_leader, label: Task Leader, short: TL,   order: 10, leads: true }
  - { id: principal,   label: 책임연구원,   short: 책임, order: 20 }
  - { id: senior,      label: 선임연구원,   short: 선임, order: 30 }
  - { id: researcher,  label: 연구원,       short: 연구원, order: 40 }

units:                      # parent 로 이어지는 일반 트리
  - { id: vs,            kind: division, name: VS본부,        parent: null }
  - { id: vs-sw-center,  kind: center,   name: SW플랫폼센터,  parent: vs }
  - { id: vs-auth-team,  kind: team,     name: 인증플랫폼팀,  parent: vs-sw-center }
```

```yaml
# config/agents.yaml — 사람
- entity_id: person:kim
  display_name: 김철수 책임
  org: { unit: vs-auth-team, rank: principal, title: 인증 아키텍트 }
  topics: [인증, SSO, 토큰 갱신, 세션 바인딩, SDK 보안]
```

### 1.2 왜 두 파일로 나눴나

두 축이 서로 다른 이유로 바뀌기 때문이다.

- 사람이 팀을 옮기면 → `agents.yaml` 의 `org.unit` **한 줄**
- 조직 개편이 일어나면 → `org.yaml` **한 곳**

`agents.yaml` 에 `"VS본부 SW플랫폼센터 인증플랫폼팀"` 같은 문자열을 적었다면,
개편 한 번에 열 사람의 열 줄을 고치고 그중 하나를 빠뜨리게 된다.

### 1.3 왜 코드가 층 이름을 모르게 했나

`본부 → 센터/연구소 → 팀` 은 **이 회사의 현재 모습일 뿐**이다.
`org.py` 에는 `division`·`center`·`team` 이라는 문자열이 **하나도 없다.**
`units` 는 `parent` 로 이어지는 일반 트리이고, 깊이는 데이터가 정한다.

화면(`app.js`)도 마찬가지다. `renderUnit()` 은 재귀이고 층 이름은
서버가 준 `kind_label` 로 온다. `"팀"` 이라는 단어가 JS 에 없다.

이것을 검사하는 방법은 **이 회사와 전혀 다른 조직도를 먹여 보는 것**이다 —
`tests/unit/test_org.py` 의 `alien_chart` 픽스처가 길드/챕터/스쿼드/포드 4층으로
그 일을 한다. 실물로만 테스트하면 코드가 실물의 층 이름을 알고 있어도 통과한다.

> ⚙️ **층을 하나 더 넣으려면**: `unit_kinds` 에 항목을 더하고 `units` 에
> `parent` 를 이어 붙인다. 코드·화면 변경 0.
> 상한은 `org.MAX_DEPTH`(8) 이며, 순환은 로드 시점에 막는다.

### 1.4 데모 구성 — 10명

| 본부 | 센터 | 팀 | 사람 |
|---|---|---|---|
| VS본부 | SW플랫폼센터 | 인증플랫폼팀 | 정대현 TL · 김철수 책임 · 최민수 선임 · 윤서진 선임 · 한지우 연구원 |
| VS본부 | SW플랫폼센터 | 데이터플랫폼팀 | 오세영 TL · 신동욱 책임 · 박선영 선임 · 서민아 선임 · 배현수 연구원 |
| MS본부 / HS본부 / CTO부문 | (선언만) | | 0명 — **구조가 데이터라는 것을 보이기 위한 빈 단위** |

구성원이 0명인 단위는 화면이 흐리게 접어서 그린다.
사람을 넣으려면 `agents.yaml` 에 `org.unit: ms-conn-team` 을 쓰기만 하면 된다.

### 1.5 개인 폴더 + 개인 Agent

10명 전원이 각자 폴더를 갖는다. 구조는 기존과 같다.

```
agents/person_yoon/
  data/                     ← 이 사람의 지식. knowledge_scope 가 가리키는 곳
    docs/idp-integration-notes.md
    docs/token-lifetime-policy.md
  gatekeeper/
    session.json            ← 지금 무엇을 하고 있나 (focus · open_paths · 신선도)
  security_protocol/        ← 개인 보안 프로토콜 (선택)
```

Agent 는 구현이 하나고 설정만 다르다 (FR-23). `agents.yaml` 항목 하나 =
개인 Agent 하나이며, 페르소나·지식 범위·공개 범위·일일 한도가 거기서 나온다.

새로 추가된 7명에게는 각자의 지식 문서를 넣어 두었다 — 로드맵/회의록,
IdP 연동 노트, 키 회전 런북과 스크립트, 데이터 계약, 피처 스토어 설계,
서빙 튜닝 노트와 설정, 평가 지표와 실행 로그.

### 1.6 조직도는 인증 없이 보이는 화면이다

`GET /api/org` 응답은 `org.yaml` 의 문자열을 그대로 내보낸다.
여기에 고객사명이 실리면 **게이트키퍼를 우회한 유출**이다 (FR-31 과 같은 위험).

그래서 `OrgChart.validate_no_banned()` 가 **로드 시점에** 금칙어를 검사하고,
걸리면 앱이 뜨지 않는다. `topics` 도 같은 이유로
`triage.validate_topics()` 가 검사한다 (`tests/unit/test_triage.py` 가 실물을 검사).

### 1.7 자리를 못 찾은 사람은 사라지지 않는다

`org.unit` 에 오타가 나면 그 사람은 `unplaced_member_ids` 로 빠지고,
화면은 **"미배치 — 조직도에 자리가 없는 사람"** 묶음에 그린다.

조용히 사라지면 "왜 안 보이지" 가 되고, 그건 디버깅이 아니라 수색이 된다.

### 1.8 조직도가 없어도 앱은 뜬다

`config/org.yaml` 이 없으면 `load_org()` 가 빈 차트를 준다 (예외를 올리지 않는다).
카드의 조직 좌표는 전부 `None` 이 되고, 화면은 평평한 목록으로 떨어진다.
조직도는 **표시용**이고, 없다고 질의가 막혀서는 안 된다.

다만 **형식이 틀리면** 올린다. 없는 것과 틀린 것은 다르다.

## 2. 브로드캐스트

### 2.1 무엇을 바꿨나

질문을 입력하면 `POST /api/ask/broadcast` 가 **전원의 Agent** 에게 방송하고,
각자 "이 질문에 내가 답할 수 있는가" 를 판정한다.

```jsonc
// 응답 (요약)
{
  "broadcast_id": "bc_…",
  "results": [                       // ⚠️ 전원이 들어 있다. 관련 없는 사람도
    { "entity_id": "person:kim", "relevant": true,  "score": 1.0,
      "reason_code": "topic_match", "reason": "세션 바인딩 — 담당하는 주제입니다",
      "matched": ["세션 바인딩"], "decided_by": "rule" },
    { "entity_id": "person:park", "relevant": false, "score": 0.0,
      "reason": "이 질문과 겹치는 담당 영역이 없습니다" }
  ],
  "model_used": true,
  "crossed_boundary": false          // ⚠️ Literal[False] — 타입이 약속한다
}
```

### 2.2 원래 "구현하지 않은 것" 이었다 — 왜 이제 괜찮은가

`orchestrator.py` 는 브로드캐스트를 **의도적으로 빼 두고** 그 근거로
*"기밀 질문이 전사에 뿌려질 일 없음"* 을 들었다. 그 근거를 다시 세워야 한다.

**세 가지가 성립하므로 위험이 따라 들어오지 않는다.**

**① 질문이 남에게 도달하지 않는다.**
선별은 이 노드 안에서 끝난다. 인박스에 쓰지 않고 알림을 만들지 않는다.
`prepare` 의 `agents_notified: Literal[False]` 와 같은 약속이,
브로드캐스트에서는 `BroadcastResult.crossed_boundary: Literal[False]` 다.

**② 판정이 남의 문서를 읽지 않는다.**
판정 재료는 이것뿐이다.

| 재료 | 어디서 | 이미 공개인가 |
|---|---|---|
| `expertise` · `topics` | `agents.yaml` — 본인이 적은 것 | ✓ 카드에 뜬다 |
| 조직 단위 이름 | `org.yaml` | ✓ 조직도에 뜬다 |
| `current_focus_summary` | 게이트키퍼를 **이미 지난** 주제 라벨 | ✓ 카드에 뜬다 |

전부 이미 인증 없이 보이는 값이다. 그래서 열 명에게 뿌려도 **새로 노출되는 것이 0** 이다.

만약 판정이 문서 본문을 읽었다면, *"박선영이 이 질문에 답할 수 있다"* 는
결과 자체가 박선영의 파일에 무엇이 있는지를 알려주는 채널이 된다.
그것은 게이트키퍼를 우회한 유출이다.

이 성질은 주석이 아니라 **타입**이다 — `triage.Candidate` 에는 본문·경로·
문서 제목을 담을 자리가 **없다**. `tests/unit/test_triage.py::
test_candidate_has_no_field_for_document_text` 가 그 자리를 고정한다.

**③ 선별이 전송을 결정하지 않는다.**
선별 결과는 목록을 줄일 뿐이다. 무엇이 경계를 넘을지는 사용자가 사람을 고른 뒤
`prepare()` 부터 게이트키퍼가 다시 정한다. 선별을 속여서 얻는 것은
"후보 목록에 남는 것" 뿐이다.

### 2.3 판정은 두 겹이다

```
① 규칙   질문 ↔ topics/expertise/단위 이름의 겹침.  순수 함수. 항상 돈다
② 모델   EXAONE 이 번호와 사유 코드만 고른다.       실패하면 ①만 쓴다
```

**등급 판정과 방향이 반대인 것에 주의한다.**

|  | 등급 판정 (`classifier`) | 선별 (`triage`) |
|---|---|---|
| 합치는 방식 | 둘 중 **높은** 쪽 | 둘 중 **넓은** 쪽 |
| 실패하면 | 기밀로 간주 (fail **closed**) | 규칙 결과만 사용 (fail **open**) |
| 근거 | 낮게 잡은 실수 = 유출 | 좁게 잡은 실수 = 답할 사람이 사라짐 |

위험이 비대칭이므로 기본값도 비대칭이어야 한다. 전자는 되돌릴 수 없고,
후자는 사용자가 **"전체 보기"** 를 누르면 끝난다.

### 2.4 모델에게 자유 문장을 만들게 하지 않는다

모델이 돌려주는 것은 **후보 번호와 닫힌 집합의 사유 코드**뿐이다.

```json
{"picks": [{"i": 3, "code": "topic_match"}]}
```

화면에 뜨는 문장은 `triage.REASON_TEMPLATES` 를 써서 **코드가 조립한다.**
구조 추출의 슬롯 채우기와 같은 원칙이다 — 자유 문장을 허용하면 판정 결과에
원문이 섞여 나올 채널이 하나 생긴다.

번호만 받는 이유는 `store.select_paths()` 와 같다. 문자열을 만들게 하면
존재하지 않는 것을 만들어낸다 — 거기서는 없는 경로, 여기서는 없는 사람이다.
범위 밖 번호와 미등록 코드는 파싱에서 버린다.

> ⚙️ **문구를 바꾸려면**: `REASON_TEMPLATES` 표만 고친다. 판정 로직은 그대로다.
> ⚙️ **사유 코드를 늘리려면**: `ReasonCode` 와 `REASON_TEMPLATES` 에 항목을 더하고,
> `TRIAGE_SYSTEM` 프롬프트의 목록에 한 줄 넣는다.

### 2.5 관련 없는 사람을 목록에서 지우지 않는다

`results` 는 **전원**을 담고, 화면은 관련 없는 사람을 흐리게(`is-dimmed`) 그린다.
지워 버리면 판정이 틀렸을 때 사용자가 되돌릴 대상이 없다.
흐려진 카드도 누를 수 있고, 누르면 그 사람과의 대화가 열린다.

`BROADCAST_MAX_RELEVANT` 를 넘는 인원은 점수 낮은 쪽부터 후보에서 빠지지만,
**목록에서는 그대로 남는다.**

### ⚙️ 조정 지점

| 환경변수 | 기본값 | 뜻 |
|---|---|---|
| `BROADCAST_THRESHOLD` | `0.5` | 후보로 남길 점수 하한 |
| `BROADCAST_MAX_RELEVANT` | `6` | 한 번에 후보로 남길 최대 인원 |

가중치는 `triage.py` 상단에 모여 있다 (`WEIGHT_TOPIC` 등). 값의 근거는
**"얼마나 본인이 직접 선언한 것인가"** 다 — `topics` 는 본인이 이 질문을
받겠다고 적어 둔 것이라 가장 세고, 단위 이름은 같은 팀이면 누구나 걸리므로 가장 약하다.

### 2.6 한국어 매칭

형태소 분석기를 붙이지 않았다. 사전이 하나 늘면 그것도 관리 대상이 되고,
여기서 필요한 정밀도는 "겹치는가" 수준이다.

- `strip_suffix()` — 조사 꼬리 자르기 (`라벨을` → `라벨`).
  자른 뒤 2글자 미만이면 원형을 남긴다
- `compact()` — 공백 제거 후 구(phrase) 포함 검사 (`라벨 불균형` ↔ `라벨불균형을`)
- 구를 이루는 토큰이 **전부** 질문에 있으면 그 구가 나온 것으로 본다

### 2.7 화면에서 일어나는 일

1. 질문 전송 → `org-panel` 에 `.broadcasting` — 파동(ripple) 3겹이 퍼진다
2. 카드마다 `--ping-delay` 를 다르게 줘 순서대로 반응한다 (테두리 + 미세 이동)
3. 응답이 **즉시 와도** 파동을 `WAVE_MIN_MS`(900ms) 동안 보여준다 —
   "지금 열 명에게 물었다" 는 사실이 보여야 하기 때문이다. 장식이 아니라 상태 표시다
4. 판정 도착 → 관련 없는 사람은 `opacity: 0.28` + 채도 down, 관련 있는 사람은
   테두리 강조 + 선별 근거 한 줄
5. 사람을 누르면 **왼쪽에 그 사람과의 스레드**가 열리고, 뿌려 둔 질문이 이어서 전송된다

> 인라인 `style=` 속성을 HTML 에 쓰지 않는다 (CSP + `lint_web.py`).
> 지연값은 JS 가 `card.style.setProperty("--ping-delay", …)` 로 넣는다.

### 2.8 스레드

사람마다 대화가 따로 쌓인다 (`state.threads[entity_id]`).
메시지를 **데이터로** 들고 다시 그린다 — DOM 을 들고 있으면 스레드를 오갈 때
어느 말풍선이 어느 스레드 것인지가 화면 상태에만 남고, 사용자를 전환하거나
조직도를 새로 그리는 순간 어긋난다.

입력창의 동작이 스레드에 따라 갈린다.

| 화면 | Enter 를 누르면 |
|---|---|
| 브로드캐스트 (기본) | 전원에게 방송 |
| 사람 스레드 | 그 사람에게만 `prepare` → `send` |

`← 전체에게 묻기` 로 언제든 방송 화면으로 돌아간다.

## 3. 처리 경과 (게이트키퍼 트레이스)

### 3.1 무엇을 바꿨나

말풍선 아래 접혀 있던 `Gatekeeper: 통과` 한 줄이 **6단계로 펼쳐지고**,
각 단계를 누르면 그 단계가 **실제로 손에 쥐고 있던 자료**가 열린다.

| # | 단계 | 무엇을 보여주나 |
|---|---|---|
| ① | 등급 판정 | 대상별 규칙/EXAONE/최종 등급 표 + 이 등급이 뜻하는 것 |
| ② | 근거 선택 | 동원된 문서의 제목·등급·종류·시점·분량 + 어떻게 골랐나 |
| ③ | 표현 변환 | **경계를 넘은 JSON 전문** + 치환 기호표 + 어떻게 만들었나 |
| ④ | 검증 6단계 | 단계별 통과/차단 + 가려진 건수 + 원문 문장 수(측정값) |
| ⑤ | 경계 통과 | 어디로 · 어떤 모델에 · 몇 바이트 · 어떤 해시 · 누구 승인으로 |
| ⑥ | 재수화 | **기호 답변 ↔ 복원된 답변 좌우 비교** + 되돌린 기호 + 인용 |

⑤ 와 ⑥ 사이에 **신뢰 경계** 선이 그어진다. 위는 노트북 안, 아래는 바깥이다.

### 3.2 "EXAONE 이 만든 데이터는 자연어인가 JSON 인가"

**등급에 따라 다르고, 화면이 그 차이를 직접 말한다.**

| 등급 | 표현 | 페이로드의 형태 |
|---|---|---|
| 기밀 | `structured` | **구조화된 JSON. 자연어 문장이 아니다.** 값이 전부 `vocab.json` 의 닫힌 어휘에서 왔고, 코드가 스키마를 순회하며 조립했다 |
| 사내 | `pseudonymized` | **자연어 문장이 그대로 있는 JSON.** 문장은 유지하고 식별자만 `<PERSON_1>` 같은 기호로 바꾼다 |
| 공개 | `verbatim` | **원문 그대로.** 공개 등급의 정의가 그것이다 |

③ 표현 변환 탭의 캡션이 이 문장을 그대로 띄우고, 그 아래에 **JSON 전문**이 있다.
용어를 정리하면 — 이것은 **암호화가 아니다.** 되돌릴 열쇠(매핑)를 만드는 것은
사내 등급의 가명화뿐이고, 기밀 등급은 되돌릴 것이 애초에 없다. 문장을 버리고
**구조만 다시 쓰는 것**이다.

### 3.3 기호 답변 ↔ 복원된 답변

⑥ 재수화 탭이 둘을 나란히 놓는다.

```
경계 밖에서 받은 것 (기호)              신뢰 구역에서 복원한 것
─────────────────────────              ─────────────────────────
이유: REQ_A 는 세션 바인딩을    →      이유: 고객사 H 5G 코어망 인증
      요구하지만 COMP_A 는                  요구사항명세서 는 세션 바인딩을
      적용하지 않는다                        요구하지만 SDK 인증 설계 문서
                                            (v3.2) 는 적용하지 않는다
```

왼쪽은 경계 **밖** 모델이 만든 그대로다 — 실제 이름을 본 적이 없다.
오른쪽은 신뢰 구역 안에서 기호를 되돌린 것이고, 재수화는 **순수 문자열 치환**이며
모델을 쓰지 않는다 (FR-13).

### 3.4 트레이스가 담지 **않는** 것 — 이 기능의 핵심 규칙

트레이스는 화면에 자료를 **더 많이** 보여주는 기능이다. 그래서 위험이 반대 방향이다.
다른 모듈은 "안 나가게" 를 지키고, 여기는 **"보여주면 안 되는 것을 애초에 담지 않기"** 를 지킨다.

**① 원문을 담지 않는다.**
보여주는 최대치는 *경계를 넘은 것*이다. 그보다 많이 보여주면 트레이스 자체가
권한 우회 통로가 된다. 질문자는 이미 미리보기에서 페이로드 전문을 봤으므로
(BR-U-01) 같은 것을 다시 보는 것은 새로운 노출이 아니다. 반면 변환 **전** 원문은
질문자가 볼 권한이 없는 남의 파일이다.

**② `CheckResult.offending` 을 담지 않는다.**
원문대조(n-gram) 검사가 실패했을 때 `offending` 에는 **원문 5-gram 이 그대로** 들어
있다. 그것을 화면에 띄우면 "검증이 막았다"고 표시하면서 동시에 막힌 내용을 보여주는
자기모순이 된다. 건수만 남긴다 — `redact_checks()`.

**③ 매핑표는 답변에 실제로 등장한 기호만 공개한다.**
`<PERSON_2> → 김철수` 를 전부 보여주면 *"김철수가 박선영의 문서에 등장한다"* 는 사실이
새어 나간다. 답변에 나온 기호는 이미 재수화된 실제 이름으로 질문자가 읽은 것이므로
공개해도 새 정보가 아니다. 나머지는 건수만 센다 — `mapping_rows(visible_in=…)`.

**④ 판정 사유에서 매치된 값을 걷어낸다.** ← *구현 중 실제로 잡은 결함*

`classifier` 가 만드는 사유 문자열은 **서버 로그용**이라 매치된 값을 그대로 품는다.

```
경로 규칙 'person_kim/data/customer-H/**' 매치     ← 내부 경로 + 고객사 디렉터리명
금칙어 '하나텔'                                    ← 애초에 막으려던 그 단어
```

첫 구현에서 이것을 그대로 화면에 실었고, 브라우저 확인에서 발견했다.
`redact_reasons()` 가 **범주만 남기고 값을 지운다.**

```
경로 규칙 매치 (경로는 표시하지 않는다)
금칙어 리터럴 매치 (해당 단어는 표시하지 않는다)
```

모르는 형태의 사유가 값을 품고 있으면(따옴표·슬래시) **통째로 가린다** —
새 규칙이 추가됐을 때 그 사유가 검사 없이 화면에 뜨는 것을 막는다 (fail closed).

**이 네 규칙은 주석이 아니라 함수다** — `redact_checks()` · `mapping_rows()` ·
`redact_reasons()`. 그리고 `tests/unit/test_trace.py` 가 각각을 고정한다.

### 3.5 왜 `Chunk` 와 `Mapping` 을 import 하지 않나

이 저장소에는 원문(`Chunk`)과 매핑(`Mapping`)을 만질 수 있는 모듈이 목록으로
고정돼 있다 (`tests/unit/test_import_boundary.py`).

트레이스를 그 목록에 **넣지 않았다.** 대신

- `Chunk` → `TraceEvidence` 로 **투영**해서 받는다.
  `text` 와 `internal_path` 를 담을 자리가 없다 (FR-43)
- `Mapping` → 호출자가 자기 책임으로 뜬 **평범한 dict** 로 받는다

투영을 만드는 책임은 **이미 원문을 다루는 쪽**(`orchestrator._evidence()`)에 남는다.
규칙에 예외를 하나 내는 것보다, 원문을 만질 수 있는 모듈을 늘리지 않는 편이 낫다.

"받아 놓고 안 쓴다" 와 "받지 않는다" 는 다르다. 앞의 것은 다음 사람이 한 줄
추가하면 유출이 되고, 뒤의 것은 타입이 막는다.

### 3.6 트레이스는 감사 로그가 아니다

| | 감사 로그 (`audit.py`) | 트레이스 (`trace.py`) |
|---|---|---|
| 무엇 | 법적 증거 | 사람이 이해하기 위한 화면 |
| 저장 | SQLite (영속, PITR) | **메모리만** |
| 수명 | 영구 | TTL 30분 · 최대 200건 |
| 담는 것 | 경계를 넘은 페이로드 | 위 + 답변에 등장한 기호의 값 |

둘을 합치지 않는 이유가 여기 있다. 트레이스는 매핑표의 일부를 품고 있고,
그것이 디스크에 남으면 `Mapping` 이 직렬화 불가인 이유(BR-G-09)를 우회하는 셈이 된다.
`test_store_is_memory_only` 가 `trace.py` 에 파일 쓰기 호출이 없음을 AST 로 검사한다.

TTL 이 지나면 `GET /api/trace/{id}` 가 404 이고, 화면은
*"처리 경과가 만료되었습니다 (기록은 30분 뒤 사라집니다)"* 를 그린다.

### 3.7 차단된 질의야말로 경과를 보여줘야 한다

전송이 막힌 경우에도 트레이스가 남는다. 오히려 그쪽이 더 중요하다 —
"왜 답이 안 나왔나" 에 답해야 하기 때문이다.

| 어디서 막혔나 | 트레이스에 남는 것 |
|---|---|
| 근거 없음 | ② 근거 선택 = `blocked` — "동원할 근거가 없다" |
| 구조 추출 실패 (기밀) | ③ 표현 변환 = `blocked` — "기밀은 원문으로 나가지 않는다" |
| 검증 실패 | ⑤ 경계 통과 = `blocked` — 어느 단계에서 막혔는지 + 감사 레코드가 없다는 사실 |
| 그 외 준비 실패 | ⑤ 경계 통과 = `blocked` — 사유 |

차단 사유는 **한 번만** 적는다 (`TraceRecorder.has_blocked`).
두 개면 읽는 사람이 어느 것이 진짜인지 모른다.

### 3.8 기록 실패가 질의를 죽이지 않는다

모든 `add_*` 는 예외를 삼키고 로그만 남긴다. `TraceStore` 가 없으면 기록기를
아예 만들지 않고, 그때 `trace_id` 는 `None` 이며 화면은 "단계별로 보기" 버튼을
그리지 않는다. **트레이스는 설명이지 기능이 아니다.**

`test_recorder_never_raises_on_bad_input` 이 이것을 고정한다.

### 3.9 왜 말풍선 안이 아니라 모달인가

JSON 전문과 좌우 비교는 말풍선 폭에서 읽히지 않는다.
전문을 보여준다면서 좁은 칸에 밀어 넣는 것은 접어 두는 것과 다르지 않다 (BR-U-01).

말풍선에는 결과 한 줄(`gk-strip`)만 남고 — 등급 배지, 통과/차단, "단계별로 보기" —
누르면 모달이 열린다. 단계는 `role="tablist"` / `role="tabpanel"` 로 접근 가능하다.

트레이스는 **처음 열 때** 가져온다. 말풍선마다 미리 받으면 쓰지도 않을 6단계를
전부 들고 있게 된다. 한 번 받은 것은 `state.traces` 에 캐시한다.

> ⚙️ **단계를 추가하려면**: `trace.STAGE_DEFS` 에 항목을 더하고, 그 단계를
> 기록하는 쪽에서 `rec.put(stage_id, …)` 를 부른다. 순서·제목·부제가 한 곳에 있다.
> ⚙️ **자료의 종류를 추가하려면**: `PanelKind` 에 종류를 더하고 `app.js` 의
> `renderPanel()` 에 `case` 를 하나 넣는다.
> `TracePanel` 에 **HTML 을 담는 필드가 없는 것**이 의도다 —
> 화면이 `innerHTML` 을 쓸 수 없게 하는 타입 수준 장치다 (BR-U-12).

## 4. 확장성 — "데모를 하드코딩하지 않았다" 의 근거

| 하고 싶은 일 | 고칠 곳 | 코드 변경 |
|---|---|---|
| 사람 추가 | `config/agents.yaml` 항목 하나 + `agents/person_*/` 폴더 | 없음 |
| 사람의 팀 이동 | `agents.yaml` 의 `org.unit` 한 줄 | 없음 |
| 조직 개편 | `config/org.yaml` | 없음 |
| **계층을 하나 더** (예: 본부 위에 부문) | `org.yaml` 의 `unit_kinds` + `units` | 없음 |
| 직급 추가 / 정렬 변경 | `org.yaml` 의 `ranks` | 없음 |
| 선별 키워드 조정 | `agents.yaml` 의 `topics` | 없음 |
| 선별 강도 조정 | `BROADCAST_THRESHOLD` / `BROADCAST_MAX_RELEVANT` | 없음 |
| 선별 사유 문구 변경 | `triage.REASON_TEMPLATES` | 표만 |
| 트레이스 단계 추가 | `trace.STAGE_DEFS` + 기록 호출 | 최소 |
| 보안 규칙 변경 | 화면의 **보안 프로토콜** 모달 (재시작 불필요) | 없음 |

**하드코딩하지 않기 위해 실제로 한 일** — 목록을 손으로 적는 곳을 없앴다.

- `tests/conftest.py` 가 사람 목록을 `config/agents.yaml` 에서 읽는다.
  전에는 `("person_kim", "person_park", "person_choi")` 를 손으로 적었고,
  사람을 추가하면 그 사람만 세션 없이 테스트를 돌았다
- `test_api.py` 의 인원 검사가 `set(wiring.data.agents)` 와 비교한다.
  전에는 세 명을 손으로 적었고, 그러면 FR-23("추가는 항목 하나로 끝난다")이
  테스트에서 거짓이 된다
- 화면의 층 이름·사람 목록·질문 프리셋이 전부 서버에서 온다

## 6. 알려진 한계

**목업 모드에서 선별은 규칙만으로 돈다.**
`EXAONE_MODE=mock` 에서는 `triage` 픽스처가 없어 모델 판정이 실패하고,
화면이 *"선별 모델을 쓰지 못해 규칙만으로 좁혔습니다"* 를 표시한다.
설계된 fail-open 동작이며 선별 자체는 정상이다. 라이브 모드에서는 두 겹이 다 돈다.
(픽스처를 녹화하려면 `MESH_RECORD_FIXTURES=1 EXAONE_MODE=live`.)

**목업 모드는 녹화된 질문에서만 완전히 돈다.**
`prepare` 가 `select_paths` · `extract` · `fallback` 픽스처를 요구하므로,
녹화되지 않은 문장을 넣으면 그 대상에서 400 이 난다. 이번 변경 이전부터의 성질이다.

**선별은 어휘 겹침이지 의미 이해가 아니다.**
규칙 층은 표기가 다르면 놓친다 (`클래스 쏠림` vs `라벨 불균형`).
그 간극을 메우는 것이 모델 층이고, 모델이 없으면 사용자가 **"전체 보기"** 로
직접 고른다. 선별은 목록을 줄일 뿐 사람을 대신하지 않는다 (FR-29).

**인증은 여전히 없다.** 사용자 전환은 데모용이고 화면이 그 사실을 표시한다.
브로드캐스트는 전환된 사용자를 자기 자신에서 제외할 뿐, 권한을 판단하지 않는다.
실배포 전제는 **원본 시스템의 접근 권한 승계**다.
