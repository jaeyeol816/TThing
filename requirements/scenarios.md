# 예시 시나리오 3종 — 단계별 흐름

> 설계안(`hackathon-mvp-design.md`)이 실제로 어떻게 도는지 세 가지 상황으로 따라간다.
> 대리 대상은 **사람만**이다 (끝난 프로젝트용 에이전트는 이번 범위에서 제외).
> 검토용 문서이며, 구현 전 합의가 필요한 지점은 §5에 모아 두었다.

---

## 0. 전제 — Knowledge Store는 세션 + 파일

세 시나리오 모두 이 전제 위에서 돈다. 벡터 DB나 RAG 인덱스는 쓰지 않는다.

### 0.1 구조

```
[데몬] ──실시간 감시──> [개인 세션]  ──필요할 때──> [파일 직접 읽기]
 작업 모니터링            메모리/JSON              경로를 이미 알고 있으므로
                                                  인덱스 없이 바로 읽는다
```

**세션에 담기는 것** (사람마다 하나)

```json
{
  "entity_id": "person:kim",
  "updated_at": "2026-08-19T14:31:20+09:00",
  "focus": "고객사 H 인증 요구사항 검토 + SDK v3.2 토큰 정책",
  "summary": "고객사 H의 인증 요구사항과 자사 SDK 토큰 갱신 정책의 정합성을 검토 중",
  "open_paths": ["~/work/sdk/docs/auth-design.md", "~/work/customer-H/req-spec-2026H.md"],
  "recent_edits": [{ "path": "~/work/sdk/src/auth/token.py", "at": "2026-08-19T11:02" }],
  "recent_runs": [],
  "datasets": []
}
```

**검색이 아니라 지목이다.** 질문이 오면 임베딩으로 청크를 뒤지는 게 아니라, 세션이 이미 좁혀 놓은 후보 경로 중에서 고르고 그 파일만 읽는다. 세션에 없는 것은 못 찾는다 — 이건 한계이자, 동시에 "지금 이 사람의 관심사"라는 강력한 사전 필터다.

### 0.2 자리에 없어도 답한다

세션은 사람이 자리를 비워도 마지막 상태로 남아 있고, 파일은 언제든 읽힌다.

| 사람의 상태 | 세션 | 에이전트가 답할 수 있는 것 |
|---|---|---|
| 작업 중 | 실시간 갱신 | 지금 뭘 하는지까지 |
| 자리 비움 · 퇴근 | 마지막 상태로 정지 | 마지막 시점 기준 + 파일 전부 |
| 장기 부재 | 오래된 상태 | 파일 위주. 답변에 세션 기준 시각 명시 |

**"물어볼 사람이 자리에 없다"가 더 이상 대기 사유가 되지 않는다.** 시나리오 3에서 최민수는 두 시간째 부재중이지만 그의 에이전트는 답한다.

### 0.3 최신성이라는 이점

인덱스는 항상 뒤처진다. 세션은 실시간이다. 그래서 **"박선임이 지금 그 스크립트를 돌리고 있다"** 같은 답이 가능해진다 (시나리오 2). 어떤 벡터 DB도 이건 못 담는다.

### 0.4 구현이 버거우면

데몬 전체를 만들지 않아도 시나리오는 성립한다.

| 정식 | 데모 대체 |
|---|---|
| 파일시스템 감시 데몬 | 미리 작성한 세션 JSON 3개 + 시연 중 수동 갱신 |
| 실행 중 프로세스 추적 | 세션에 `recent_runs`를 하드코딩 |
| 증분 갱신 | 앱 시작 시 1회 로드 |

**세션의 존재와 그것이 답에 미치는 영향만 보이면 데모 목적은 달성된다.** 세션을 어떻게 채우는지는 구현 난이도에 맞춰 조절한다.

## 시나리오 1 — 고객사 스펙 문서 (기밀 경로)

### 상황

| | |
|---|---|
| **질문자** | 최민수 선임 — SDK 인증 모듈 담당. 고객사 협의에는 참여하지 않는다 |
| **대상** | 김책임 — 고객사 H 협의 담당, 인증 아키텍처 |
| **질문** | "고객사 인증 요구사항이 우리 SDK 토큰 갱신 주기랑 충돌하나요?" |
| **검증 목표** | 기밀 문서를 두고 외부 Agent가 유용한 답을 내는가. 원문이 정말 안 나가는가 |

최민수는 고객사 요구사항명세서를 볼 권한도, 읽을 시간도 없다. 지금까지라면 김책임에게 물어보고 30분을 기다렸다.

### 흐름

**① 지목 — 질문자가 직접 고른다**

최민수는 인증 관련 사안이 김책임 담당임을 이미 알고 있다. 질문 화면의 목록에서 김책임 Agent를 고른다.

```
 ● 김철수 책임의 Agent      인증 · SSO · SDK 보안
   🟢 활동 중 · 오늘 3건     지금 인증 관련 작업 중
 ○ 박선영 선임의 Agent      데이터 파이프라인 · 모델 학습
 ○ 최민수 선임의 Agent      SDK 인증 모듈 · 배포 파이프라인
```

> **여기서 김책임에게는 아무 알림도 가지 않는다.** 지목된 것은 사람이 아니라 그의 대리인이다. 이 시나리오의 핵심은 "누구인지 찾아주는 것"이 아니라 **"찾은 사람을 깨우지 않는 것"** 이다.

**② 지식 지목 — 세션에서 후보 경로를 고른다**

김책임 세션의 `open_paths` 중 질문과 관련된 둘을 고른다. EXAONE이 로컬에서 판단한다.

| 경로 | 선택 이유 |
|---|---|
| `~/work/customer-H/req-spec-2026H.md` | 세션 `focus`에 "고객사 H 인증 요구사항" |
| `~/work/sdk/docs/auth-design.md` | 세션 `focus`에 "SDK v3.2 토큰 정책" |

**③ Gatekeeper 관문 ① — 질문 등급 판정**

| 판정기 | 결과 | 근거 |
|---|---|---|
| 규칙 | 사내 | "고객사"라는 단어는 있으나 고객사명·계약번호·요구사항 번호 없음 |
| EXAONE | 사내 | 문맥상 일반적 정합성 질문 |

질문 자체는 사내다. **그런데 여기서 끝내면 안 된다.**

> **등급은 질문 단위가 아니라, 이 답을 만드는 데 동원되는 것 전체에 걸린다.**
> 다음 단계에서 읽을 파일 중 기밀이 하나라도 있으면 **이 호출 전체가 기밀로 상향**된다.

**④ 읽은 파일의 등급 판정**

| 경로 | 등급 | 판정 근거 |
|---|---|---|
| `~/work/customer-H/req-spec-2026H.md` | **기밀** | 경로 규칙 `customer-*/**` + 문서 헤더 보안등급 |
| `~/work/sdk/docs/auth-design.md` | 사내 | 자사 설계 문서 |

→ 최고 등급 = **기밀**. 이 호출 전체가 기밀 경로로 간다.

**⑤ Gatekeeper 관문 ② — EXAONE이 구조를 뽑는다** *(원문을 보는 유일한 지점)*

사내망 서버의 EXAONE이 두 파일을 읽고, `vocab.json`이 허용하는 값만 골라 채운다. 요약이 아니라 **분류**다. 파일 원문은 내 PC에서 사내 서버로만 이동하며 사내망을 벗어나지 않는다.

Agent에게 갈 페이로드 — **이것이 전부다**:

```json
{
  "task": "constraint_conflict_check",
  "domain": "authentication",
  "entities": [
    { "ref": "REQ_A", "role": "external_requirement",
      "facts": {
        "auth_mechanism_class": "challenge_response",
        "session_binding": "required",
        "credential_reuse_allowed": false,
        "max_session_hours": 8 } },
    { "ref": "COMP_B", "role": "our_component",
      "facts": {
        "credential_lifetime_hours": 24,
        "renewal_mode": "background_silent",
        "session_binding": "none" } }
  ],
  "question_template": "conflict_and_mitigation",
  "answer_format": { "conflict": "bool", "reason": "string", "mitigations": "string[]" }
}
```

앱(내 PC) 메모리에만 남는 매핑 테이블 — EXAONE 서버에도 남기지 않는다:

```json
{ "REQ_A": "고객사 H · REQ-4412 (req-spec-2026H.md §3.2)",
  "COMP_B": "자사 SDK v3.2 토큰 정책 (auth-design.md §5)" }
```

**⑥ Gatekeeper 관문 ③ 직전 — 검증 6단계**

| # | 검사 | 결과 |
|---|---|---|
| 1 | 스키마 — 정의된 키만 있는가 | ✅ |
| 2 | 어휘 — 모든 문자열이 `vocab.json`에 있는가 | ✅ |
| 3 | 범위 — 숫자가 허용 범위인가 | ✅ `8`, `24` |
| 4 | 금칙어 — 고객사명 사전, 계약번호·요구사항번호 정규식 | ✅ 0건 |
| 5 | **원문 대조 — 원본 5-gram이 페이로드에 있는가** | ✅ **0건** |
| 6 | 크기 — 2KB 이하인가 | ✅ 1.1KB |

**⑦ 사람 확인 — 나갈 내용을 눈으로 본다**

화면에 위 JSON 전문이 뜬다. 최민수가 직접 읽는다.

```
┌─ 이 내용이 김책임 Agent(Claude)에게 전송됩니다 ──────────────┐
│  [기밀] 원문 문장 0개 · 1.1KB · 검증 6/6 통과                │
│                                                              │
│  { "task": "constraint_conflict_check", ... }                │
│                                                              │
│  포함되지 않은 것: 고객사명 · 제품명 · 요구사항 번호 · 원문   │
│                            [ 전송 ]   [ 취소 ]               │
└──────────────────────────────────────────────────────────────┘
```

> **JSON 20줄이라 3초면 읽는다.** 자유 텍스트 요약이었다면 이 관문은 현실적으로 작동하지 않는다.

**⑧ Agent 호출** *(외부 · Claude · 이 흐름에서 유일한 외부 지점)*

시스템 프롬프트:
```
당신은 김철수 책임의 Agent입니다. 1인칭으로 김책임인 척하지 마십시오.
당신이 받은 것은 실제 문서가 아니라 구조 요약입니다.
답변에서 대상은 반드시 참조 기호(REQ_A, COMP_B)로 지칭하십시오.
근거가 부족하면 추측하지 말고 confidence를 낮게 보고하십시오.
```

Claude 응답:
```json
{
  "conflict": true,
  "reason": "REQ_A는 인증을 세션에 바인딩하고 자격증명 재사용을 금지하며 세션 상한이 8시간이다.
             COMP_B는 자격증명 수명이 24시간이고 세션과 무관하게 무음 갱신한다.
             세션 종료 후에도 자격증명이 최대 16시간 유효하게 남으므로 REQ_A의 재사용 금지 조항에 위배된다.",
  "mitigations": [
    "COMP_B의 자격증명 수명을 REQ_A의 세션 상한 이하로 낮춘다",
    "세션 종료 이벤트에 자격증명 무효화를 연동한다",
    "무음 갱신 시 세션 유효성을 재확인하는 단계를 넣는다"
  ],
  "confidence": 0.83,
  "citations": ["REQ_A", "COMP_B"]
}
```

**⑨ Gatekeeper 관문 ③ — 재수화** *(내 PC · 순수 문자열 치환)*

`REQ_A` → `고객사 H REQ-4412`, `COMP_B` → `SDK v3.2`

**⑩ 최민수 화면**

```
김철수 책임의 Agent  ·  [기밀 · 사내 처리]  ·  신뢰도 0.83  ·  Agent 응답

충돌합니다. 고객사 H REQ-4412는 인증을 세션에 바인딩하고 자격증명 재사용을
금지하며 세션 상한이 8시간입니다. SDK v3.2는 토큰 수명이 24시간이고 세션과
무관하게 무음 갱신하므로, 세션 종료 후에도 토큰이 최대 16시간 유효하게
남습니다. 이는 재사용 금지 조항에 위배됩니다.

완화안
 1. SDK 토큰 수명을 세션 상한(8시간) 이하로 낮춘다
 2. 세션 종료 이벤트에 토큰 무효화를 연동한다
 3. 무음 갱신 시 세션 유효성을 재확인한다

근거  📄 고객사 H 요구사항명세서 §3.2  [기밀]
      📄 SDK 인증 설계 문서 §5        [사내]
                                        [ 직접 물어보기 ]
```

**⑪ 감사 로그 + 카운터**

```
2026-08-19 14:33:41 | 최민수 | claude-sonnet-5 | tier=secret
  payload_sha256=9f2a… | 1.1KB | 구조요약(원문 0) | 검증 6/6 | 사용자 승인
```

감사 로그 탭에서 `REQ-4412`, `EAP-AKA`, `H社` 로 검색 → **각 0건.** 사내망을 벗어난 적이 없다.

카운터: **방지된 인터럽트 1건 · 절감 추정 20분.** 김책임은 이 대화를 몰랐다.

### 분기 — 신뢰도가 낮았다면

구조 요약만으로 판단이 안 되는 경우(예: 요구사항에 예외 조항이 있는데 어휘 사전에 그 필드가 없음) Claude가 `confidence: 0.41`을 보고한다.

→ 0.45 미만 → **자동 응답하지 않고 에스컬레이션.** 김책임 인박스에 요약·근거·초안이 함께 도착하고, 최민수 화면에는 *"담당자에게 전달했습니다 (예상 8시간 내)"*.

### 이 시나리오가 증명하는 것

- 기밀 문서를 두고도 외부 Agent가 **실질적으로 유용한 답**을 낸다
- 원문은 ⑤에서 사내망 EXAONE만 보고, 경계를 넘은 것은 열거값 JSON뿐이다
- "유출 0건"이 주장이 아니라 **감사 로그 검색으로 증명**된다
- 등급 상향 규칙: 질문이 사내여도 **동원되는 지식이 기밀이면 전체가 기밀**

## 시나리오 2 — AI 모델 학습 협업 (세션의 진가)

### 상황

| | |
|---|---|
| **질문자** | 정연구원 — 다른 팀. 같은 데이터로 실험을 하나 돌려보려 한다 |
| **대상** | 박선임 — 데이터 파이프라인 + 모델 학습 |
| **질문** | "박선임님 전처리 v3에서 라벨 불균형 어떻게 처리하셨어요? 그리고 지금 그 스크립트 돌려봐도 되나요?" |
| **검증 목표** | 문서에 없는 지식을 세션이 답하는가. 사내 등급의 **가명화 경로**. 질문 분해와 에스컬레이션 |

이 질문의 답은 **어떤 문서에도 없다.** 위키에도, Jira에도 없다. 박선임의 작업 환경에만 있고, 절반은 *지금 이 순간의 상태*다.

### 박선임의 세션 (데몬이 방금 갱신)

```json
{
  "entity_id": "person:park",
  "updated_at": "2026-08-19T14:33:05+09:00",
  "focus": "atlas-ml 전처리 v3 재학습",
  "summary": "고객 로그 파생 데이터셋 v3로 재학습 중. 라벨 불균형 처리 방식을 조정함",
  "open_paths": ["~/work/atlas-ml/preprocess_v3.py", "~/work/atlas-ml/configs/v3.yaml"],
  "recent_edits": [{ "path": "~/work/atlas-ml/preprocess_v3.py", "at": "2026-08-19T13:47" }],
  "recent_runs": [
    { "cmd": "python train.py --config configs/v3.yaml",
      "started_at": "2026-08-19T14:02", "status": "running",
      "eta": "2026-08-19T17:10", "gpu": "cuda:0",
      "log": "~/work/atlas-ml/runs/2026-08-19/train.log" }
  ],
  "datasets": [
    { "path": "~/work/atlas-ml/data/preproc_v3/", "rows": 420135,
      "derived_from": "customer-H session logs", "tier": "secret" }
  ]
}
```

### 흐름

**① 지목**

정연구원은 이 데이터 작업이 박선임 담당임을 안다. 목록에서 박선영 선임의 Agent를 고른다. 목록에 `🟢 활동 중 · 지금 학습 실행 중`이 떠 있어 **선택에 확신이 선다** — 세션 정보가 라우팅이 아니라 사용자의 판단을 돕는 데 쓰인다.

**② Gatekeeper 관문 ① — 질문을 분해한다**

질문이 성격이 다른 두 개를 담고 있고, **필요한 등급도 다르다.**

```json
{ "sub_questions": [
    { "id": "q1", "kind": "technique",
      "text": "전처리 v3의 라벨 불균형 처리 방식",
      "needs": ["preprocess_v3.py", "configs/v3.yaml"], "tier": "internal" },
    { "id": "q2", "kind": "current_state_and_permission",
      "text": "지금 그 스크립트를 실행해도 되는가",
      "needs": ["session.recent_runs"], "tier": "internal" }
] }
```

> **한 번의 Agent 호출에는 한 등급만 담는다.** 가명화 원문과 구조 요약을 한 페이로드에 섞으면 둘을 대조해 원문이 복원될 수 있고, 검증도 복잡해진다. 등급이 갈리면 **호출을 나눈다.**

여기서 데이터셋 자체는 기밀이지만, **q1은 데이터를 볼 필요가 없다.** 답은 코드에 있다. 그래서 q1은 사내로 처리된다. 정연구원은 실제 라벨 분포 수치를 묻지 않았다.

**③ 지식 지목 + 관문 ② — 사내 경로는 가명화**

`preprocess_v3.py`에서 관련 부분을 읽고, EXAONE이 식별자만 치환한다. **기밀 경로와 달리 원문의 논리가 살아 있다.**

```
원문    from atlas_ml.sampling import RandomOverSampler
        sampler = RandomOverSampler(sampling_strategy=0.5, random_state=42)
        class_weight = "balanced_subsample"

가명화  from <PROJ_1>.sampling import RandomOverSampler
        sampler = RandomOverSampler(sampling_strategy=0.5, random_state=42)
        class_weight = "balanced_subsample"
```

기술 용어(`RandomOverSampler`, `balanced_subsample`)는 **치환하지 않는다.** 치환하면 답변 품질이 무너진다. 사내 등급에서 지우는 것은 사내 프로젝트명·경로 같은 식별자뿐이다.

세션에서 온 사실은 그대로 전달된다 (사내):

```json
{ "session_facts": {
    "run_status": "running", "started_at": "2026-08-19T14:02",
    "eta": "2026-08-19T17:10", "gpu_occupied": "cuda:0",
    "script_last_edited": "2026-08-19T13:47" } }
```

**④ 검증 → 미리보기 → Agent 호출 2회**

q1 응답 (Claude):
> "두 단계로 처리했습니다. ① `RandomOverSampler(sampling_strategy=0.5)`로 소수 클래스를 다수 클래스의 50% 수준까지 오버샘플링하고, ② 학습 시 `class_weight='balanced_subsample'`을 함께 적용했습니다. 오버샘플링만으로 1:1을 맞추지 않고 0.5에서 멈춘 뒤 클래스 가중치로 나머지를 보정하는 방식이라, 과적합을 줄이면서 재현율을 확보하려는 의도로 보입니다. `random_state=42`가 고정돼 있어 재현 가능합니다."
> `confidence: 0.86`, `citations: ["preprocess_v3.py"]` → **자동 응답**

q2 응답 (Claude):

> `confidence: 0.38` → **에스컬레이션**

### 이 시나리오가 증명하는 것

- **문서에 없는 지식을 답한다.** 세션이 없으면 이 질문은 100% 인터럽트를 만든다
- **"지금 뭘 하고 있는지"** 는 어떤 인덱스도 못 담는다. 세션 기반 Store의 결정적 이점
- **사내 등급의 가명화 경로** — 기밀의 구조 요약과 대비된다. 원문 논리가 살아 있어 답변이 구체적이다
- **질문 분해** — 등급이 갈리면 호출을 나눈다. 기밀이 하나 섞였다고 전부를 기밀로 끌어올려 답을 무디게 만들지 않는다
- **에스컬레이션의 정확한 경계** — 사실 확인은 Agent가, 허락은 사람이. 사람에게 넘어간 건 판단이 필요한 한 조각뿐이다

## 시나리오 3 — 기억이 엇갈릴 때 (충돌 · 폴백)

### 상황

| | |
|---|---|
| **질문자** | 한지원 — 입사 3주차. 인증 모듈 코드를 읽다 막혔다 |
| **대상** | 김책임 (당시 설계자) + 최민수 (당시 리뷰어) — **둘 다 지목** |
| **질문** | "우리 SDK는 왜 세션 바인딩을 안 쓰나요?" |
| **검증 목표** | 두 사람의 답이 엇갈릴 때의 **충돌 병기**, 검증 실패 시 **폴백** |

신입이 물어볼 곳이 가장 많고, 시니어를 방해하기는 가장 미안한 사람이다. **온보딩이 이 시스템의 가장 자연스러운 진입점**이다.

### 흐름

**① 지목 — 둘을 고른다**

한지원은 커밋 로그에서 두 사람 이름을 봤다. 누가 맞는지 모르니 **둘 다 고른다** (상한 2).

```
 ● 김철수 책임의 Agent      인증 · SSO · SDK 보안
   🟢 활동 중 · 오늘 3건
 ● 최민수 선임의 Agent      SDK 인증 모듈 · 배포 파이프라인
   ⚪ 자리 비움 (2시간) · 오늘 0건
```

→ 병렬 호출. 최민수가 자리에 없어도 **그의 에이전트는 답한다.** 세션은 마지막 상태로 남아 있고 파일은 그대로 읽힌다.

**② 등급 판정 → 사내**

설계 의도에 대한 질문이고, 동원되는 자료도 자사 설계 문서와 개인 메모다. 기밀 없음 → **사내 경로(가명화)**. 사내 프로젝트명만 치환되고 기술 내용은 그대로 Agent에 전달된다.

**③ 두 답이 엇갈린다**

김책임 Agent — 근거: `~/work/notes/2025-11-auth.md` (개인 메모, 2025-11)
> "동시 인증 3천 TPS에서 세션 조회 지연이 임계를 넘어 제외했습니다."
> `confidence: 0.71`

최민수 Agent — 근거: `~/work/sdk/docs/auth-review.md` (설계 리뷰, 2025-12)
> "레거시 SSO가 세션 식별자를 전파하지 않아 바인딩 자체가 불가능했습니다."
> `confidence: 0.78`

→ **`conflict: true`.** Orchestrator는 하나를 조용히 고르지 않는다.

**④ 한지원 화면 — 병기**

```

  성능 문제 — 3천 TPS에서 세션 조회 지연이 임계 초과

  📄 설계 리뷰 문서  ·  2025-12  ·  공식
```

> **조직 지식의 불일치는 그 자체로 발견할 가치가 있다.** 신입이 아니었다면 아무도 이 둘을 나란히 놓아 보지 않았을 것이다. `[확인 요청]`은 두 사람의 인박스에 같은 스레드로 들어가 중재를 유도한다.

**⑤ 후속 질문 — 폴백이 작동한다**

한지원: *"그 3천 TPS 테스트, 실제 수치가 어떻게 나왔나요?"*

| 단계 | 결과 |
|---|---|
| 등급 판정 | **기밀** — 고객 환경 실측 벤치마크. 경로 규칙 `customer-*/**` |
| 구조 추출 | EXAONE이 `p99_latency_ms: 840`, `throughput_tps: 3120` 생성 시도 |
| **검증 1단계 스키마** | ❌ **실패.** 두 필드 모두 `vocab.json`에 없다 |

→ **Agent를 호출하지 않는다.** EXAONE이 사내망 안에서 직접 답한다.

```
[기밀 · 사내망 밖으로 나간 것 없음]

확인된 것은 "임계를 넘었다"는 정성적 기록뿐입니다.
수치 열람은 고객 환경 벤치마크 권한이 필요하며,
김책임에게 확인 요청을 보냈습니다.

📄 개인 메모 · 2025-11
```

**감사 로그에 이 질의 레코드가 없다.** Agent를 부르지 않았으므로 사내망을 벗어난 것도 없다.

> 성능 수치 필드를 어휘 사전에 **의도적으로 넣지 않았다.** 사전에 없는 것은 실수로도 나갈 수 없다 — 화이트리스트 방식의 실질적 효과다.

### 이 시나리오가 증명하는 것

- **충돌을 숨기지 않는다** — 하나를 조용히 고르면 나머지 하나는 영원히 묻힌다
- **자리에 없는 사람도 답한다** — 최민수는 2시간째 자리에 없지만 그의 에이전트는 작동했다. 기존이라면 한지원은 2시간을 기다렸다
- **폴백이 조용히 작동한다** — 어휘 사전에 없는 필드는 검증 1단계에서 막히고, 답변은 사내망 안에서 나온다
- **온보딩이 가장 자연스러운 진입점** — 질문량이 가장 많고, 물어보기 가장 미안한 사람이 신입이다

## 5. 구현 전에 합의가 필요한 것

시나리오를 쓰면서 설계안이 정하지 않은 지점이 다섯 개 드러났다. 구현 요청 전에 팀이 정하는 편이 좋다.

**① 등급 상향의 단위**
시나리오 1에서는 *"동원되는 지식 중 최고 등급이 호출 전체에 걸린다"*, 시나리오 2에서는 *"등급이 갈리면 질문을 분해해 호출을 나눈다"* 로 처리했다. 둘 다 필요하지만 **언제 상향하고 언제 분해할지의 기준**이 필요하다.
→ 제안: 분해했을 때 각 조각이 **독립적으로 의미 있는 답**을 낼 수 있으면 분해, 아니면 상향.

**② 인용에서 경로를 어디까지 보여줄까**
최민수는 고객사 요구사항명세서를 볼 권한이 없는데 화면에는 문서명이 뜬다. MVP는 권한 관리가 없으니 그대로 두되, **문서명만 보이고 경로·본문은 안 보이는** 선까지가 적절해 보인다. 실배포에서는 원본 시스템 권한 승계가 필요하다.

**③ 충돌을 어디까지 자동으로 판정할까**
시나리오 3에서 두 답이 엇갈렸지만, 사실 **둘 다 맞을 수 있다**(성능 문제와 호환 문제가 함께 있었을 수도). 기계적으로 `conflict`를 띄우면 오탐이 잦아진다.
→ 제안: 자동 판정은 하지 않고, 두 답을 **항상 병기**한 뒤 시점·문서 성격만 표시한다. "엇갈립니다"라는 단정 대신 "둘 다 사실일 수 있습니다"로 서술하고 판단은 사람에게 남긴다. 데모 화면도 그렇게 잡았다.

**④ 세션 갱신이 멈췄을 때**
데몬이 죽었거나 사람이 자리를 비웠으면 세션이 오래된 상태다. 시나리오 2의 답변이 **틀린 실시간 정보**를 줄 수 있다.
→ 제안: 세션 `updated_at`이 N분 이상 지났으면 답변에 *"세션 기준 시각"* 을 명시하고 신뢰도를 낮춘다. 시나리오 2 화면의 `🔴 세션 · 14:33 기준`이 그 자리다.

**⑤ 에이전트 목록에 무엇까지 표시할까**
지목을 사람이 하므로 목록의 정보량이 곧 선택의 품질이다. 담당 영역(본인 작성)은 항상 공개해도 되지만, `"지금 인증 관련 작업 중"` 같은 세션 파생 상태는 본인이 켜고 끌 수 있어야 한다.
→ 제안: 담당 영역은 필수 공개, 활동 상태·오늘 질문 수·현재 작업 요약은 **본인 opt-in**. 데모에서는 셋 다 켜 둔다.

**⑥ 승인된 답변을 어디에 저장하나**
세션은 데몬이 계속 덮어쓰는 휘발성 상태다. 승인된 Q&A는 **세션과 별도의 영속 파일**이어야 한다.
→ 제안: `data/verified/{entity_id}.json`. 세션 로드 시 함께 읽어 붙인다.
