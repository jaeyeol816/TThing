## 2. 새 입구는 새 위험이다

업로드는 이 시스템에서 **유일하게 외부에서 들어온 이름으로 파일시스템을 건드리는
경로**다. 그래서 검사가 세 겹이고, 각 겹이 다른 것을 막는다.

```
① Path(filename).name        파일시스템 탈출
② safe_resolve()             MESH_DATA_ROOT 밖
③ in_scope()                 남의 knowledge_scope
```

②③이 겹쳐 보이지만 다르다. ②는 `../../../etc/passwd` 를, ③은 "박선임 디렉터리에
김책임 문서를 올리는" 것을 막는다.

`api_models.UploadRequest` 가 먼저 검증하지만 **그것은 신뢰의 근거가 아니다.**
사용자에게 빨리 알려주기 위한 것이고, `store.save_upload()` 가 다시 검증한다 —
스크립트·테스트는 HTTP 를 거치지 않는다.

### 2.1 벗겨서 조용히 쓰지 않는다

`sub/dir/a.md` 를 `a.md` 로 저장하면 사용자가 올린 것과 저장된 것이 달라지고,
목록에서 그걸 알 수 없다. 거부하고 이유를 말한다.

### 2.2 덮어쓰지 않는다

같은 이름이 있으면 `-1` 접미사를 붙인다. 업로드는 되돌릴 수 없는 작업이고,
조용히 덮어쓰면 원본이 사라진다.

### 2.3 텍스트로 받는다 (multipart 기각)

| 근거 | |
|---|---|
| 대상이 전부 텍스트 | 설계 문서·스크립트·설정·로그 |
| multipart 파서는 사고가 잦다 | 파일명·인코딩·경계 처리 |
| 클라이언트가 무엇을 보내는지 보여줄 수 있다 | 이 프로젝트의 원칙과 맞는다 |

바이너리를 받지 않는 것은 기능 미비가 아니라 **좁힌 범위**다.
확장자 목록의 기준은 "실행 위험"이 아니라 **"텍스트로 읽히는가"** 다 —
`.sh`·`.sql`·`.py` 는 허용한다. 배포 스크립트와 마이그레이션은 실제로 팀이 서로 묻는
지식이고, 이 시스템은 파일을 실행하지 않고 텍스트로만 읽는다.

### 2.4 올리는 즉시 등급과 **근거**를 준다

```
기밀로 판정됐습니다
  근거(규칙 2)  금칙어 '고객사 H'
  → 이 문서를 쓰는 질문은 원문 대신 구조 요약만 경계를 넘습니다
```

판정을 나중이 아니라 여기서 보여주는 이유: 답이 무뎌졌을 때 "왜?"를 되짚을 수 있어야
하고, 등급 판정이 블랙박스가 아니라는 것을 이 화면 하나로 보일 수 있다.

### 2.5 업로드는 세션 신선도를 되살리지 않는다

`attach_path()` 가 `open_paths` 만 고치고 `updated_at` 은 건드리지 않는다.

파일을 올린 것은 "그 사람이 지금 그 일을 하고 있다"가 아니다. 되살리면 오래된 세션이
업로드 한 번으로 LIVE 가 되고, STALE 신뢰도 보정(BR-S-04)이 통째로 무력화된다 —
자신 없어야 할 답이 자신 있게 나온다.

### 2.6 업로드한 문서는 `OPEN` 이 될 수 없다

`OPEN` 은 헤더 표기 *그리고* 공개 경로(`corpus/public/**`)를 함께 요구한다.
업로드는 `corpus/<사람>/uploads/` 에 저장되므로 두 번째 조건을 만족할 수 없다.

만약 헤더 한 줄로 `OPEN` 을 얻을 수 있다면, 기밀 문서 맨 위에 `보안 등급: 공개` 를
적는 것만으로 게이트키퍼를 통째로 우회할 수 있다. **하향 권한은 문서 작성자가 아니라
배치 경로에 있다.**

## 4. 화면

### 4.1 빌드 도구가 없다

`index.html` · `app.js` · `style.css` 세 파일. FastAPI 가 **명시 매핑**으로 서빙한다.
디렉터리 매핑(`StaticFiles`)을 쓰지 않아 리스팅이 원천 차단된다.

CSP 에 `unsafe-inline` 이 없으므로 인라인 `script`·`style`·이벤트 핸들러가
**동작하지 않는다.** 외부 CDN 참조도 0건이다 — SRI 가 필요 없는 이유이자 오프라인
데모의 전제다.

### 4.2 `lint-web.sh` → `lint_web.py`

bash grep 이었던 검사기를 Python 으로 바꿨다. 화면을 만들자마자 **오탐 3건**이 났다.

```
✗ internal_path   -> 주석 2건 ("internal_path 를 참조하지 않는다")
✗ innerHTML       -> 주석 1건 ("innerHTML 을 쓰지 않는다")
✗ <details>       -> 붙여넣기 폼을 접는 것 (페이로드가 아니다)
```

Day 2·Day 3 에서 같은 문제를 두 번 겪었다. **문자열 검사는 규칙을 설명하는 주석까지
잡는다.** 그러면 사람이 주석을 지우거나 검사를 약화시키는데, 둘 다 나쁘다.

새 검사기는 세 가지를 한다.

1. 주석을 먼저 제거한다 (문자열 리터럴 안의 `//` 를 오인하지 않는 상태 기계)
2. 의도된 예외를 **줄 단위 마커**로 허용한다 (`lint-web: allow <규칙>`, 상한 2건)
3. 검사 대상 영역을 좁힌다 (`<details>` 는 미리보기 모달 안에서만 금지)

### 4.3 검사기를 검사한다

`tests/unit/test_lint_web.py` (42개). **검사기를 테스트하지 않으면 검사기가 조용히
아무것도 안 할 수 있다.** 실제로 두 번 그랬다.

| 실패 | 증상 |
|---|---|
| 주석까지 잡았다 | CI 가 빨개져서 사람이 검사를 약화시켰다 |
| 마커를 주석 제거된 줄에서 찾았다 | 마커가 **전혀** 동작하지 않았다 |

두 경우 모두 "통과"를 출력했고 그 통과는 아무 의미가 없었다.
그래서 이제 심어둔 위반 12종을 규칙별로 잡는지, 주석 안의 위반은 잡지 않는지,
마커가 동작하는지를 각각 고정한다.

## 5. 데스크톱 셸

### 5.1 정적 파일을 번들하지 않았다

번들하면 origin 이 `tauri://localhost` 가 되고 `fetch("/api/...")` 가 백엔드에 도달하지
못한다. 절대 URL 로 바꾸면 `connect-src` 를 열어야 하고, 화면에 호스트가 하드코딩되고,
`lint_web.py` 의 "외부 URL 0건" 규칙이 깨진다.

**백엔드 주소를 그대로 열면 같은 origin 이 되어 FastAPI 의 CSP·보안 헤더가 그대로
적용된다.** 브라우저에서 열 때와 완전히 같은 코드 경로다.
데스크톱 셸이 보안 속성을 바꾸지 않는 것이 핵심이다.

### 5.2 창을 나중에 만든다

`tauri.conf.json` 의 `windows` 가 빈 배열이고 Rust `setup()` 에서 만든다.
백엔드 준비 전에 빈 창을 띄우면 "왜 안 되지?" 하게 된다.
120초 안에 포트가 열리지 않으면 창을 만들지 않고 실패를 알린다.

준비 확인은 TCP 연결만 본다 — HTTP 클라이언트를 의존성으로 추가하지 않기 위해서다.
포트가 열렸다면 uvicorn 이 떴다는 뜻이고, 그 뒤는 웹뷰가 확인한다.

### 5.3 실측

| 확인 | 결과 |
|---|---|
| `cargo build --release` | 성공 (1m50s) |
| `npm run tauri dev` | 창 열림 · API 왕복 확인 |
| "이미 실행 중" 경로 | 떠 있는 서버에 붙었다 |
| 백엔드 로그 전달 | `[backend:out]` 접두사로 흐른다 |

## 6. 게이트 G4 — 육안 전수가 찾은 것

### 6.1 왜 자동 검사만으로는 G4 가 아닌가

`sweep_for_leaks()` 는 원문 n-gram 과 금칙어를 기계적으로 대조한다.
강력하지만 **아는 것만 잡는다.** 잡지 못하는 것:

- 금칙어 목록에 없는 새 고객사명
- 문장을 옮기지 않고 *의미*를 옮긴 값
- 슬롯 **이름** 자체가 정보인 경우
- 값 **조합**으로 대상이 특정되는 경우

`scripts/dump_payloads.py` 가 경계를 넘은 것 전부를
`g4-payload-dump.md` 로 덤프한다. 페이로드 1건 = 섹션 1개, 전문이 절단 없이,
각 섹션에 확인 체크박스.

### 6.2 결함 ① — entity_id 가 새어 나갔다

**자동 검사는 통과했다.** 사내 등급 발췌를 눈으로 읽으니 이렇게 적혀 있었다.

```
"# owner: person:park"
```

`pseudonyms.json` 의 PERSON 목록에는 사람 이름(`박선영`)만 있었다. 코퍼스 파일 헤더는
**같은 사람의 다른 표기**를 쓴다. `sweep_for_leaks` 는 "식별자를 포함한 n-gram"만 보고,
`person:park` 는 목록에 없었으므로 **식별자가 아니었다.**

> **목록에 없는 것은 검사되지 않는다.** 이것이 G4 를 사람이 하는 이유다.

**고친 방법**: `DataBundle._add_entity_ids_to_pseudonyms()` 가 `agents.yaml` 에서
`entity_id` 와 `display_name` 을 **유도해** PERSON 대상에 넣는다.

`pseudonyms.json` 에 손으로 적지 않은 이유: `agents.yaml` 에 사람을 추가할 때 두 파일을
고쳐야 하고, 하나를 잊으면 조용히 새어 나간다. FR-23 이 "설정 한 곳"을 요구하는 것과
같은 이유다. 여기서 유도하면 **새 사람이 자동으로 보호된다.**

`person:kim` 의 지역 부분(`kim`)은 넣지 않았다. 2~3자 토큰은 본문의 무관한 단어와
충돌해 답변을 망가뜨린다 (BR-P-01 의 반대편 위험).

### 6.3 결함 ② — 미리보기가 거짓 보증을 했다

`excluded_categories` 가 **표현과 무관하게** 같은 8개 목록을 반환했다.
그런데 사내 등급 페이로드에는 이렇게 들어 있었다.

```
"title: SDK v3.2 인증 설계 리뷰 … as_of: 2025-12-03 …"
```

화면은 그 순간 "제품명 · 버전 · 일정 · 원문 문장은 포함되지 않았습니다" 라고
표시하고 있었다. **셋 다 거짓이다.**

가명화(사내)는 원문 문장을 유지하는 것이 **정의**다 — 식별자만 바꾼다.
그러니 "원문 문장 없음"을 약속할 수 없다.

**이 결함이 유출보다 나쁜 이유**: 사용자는 이 목록을 읽고 [전송] 을 누른다.
목록이 거짓이면 사용자의 판단 근거가 틀린 것이고, 그러면 **"사람이 미리보기를
확인한다"는 방어 겹 자체가 무의미해진다.**

**고친 방법**: `EXCLUDED_CATEGORIES_BY_REPRESENTATION` 을 신설했다.

| 표현 | 약속하는 것 | 근거 |
|---|---|---|
| `structured` | 8개 전부 | 코드가 닫힌 어휘에서 조립한다 |
| `pseudonymized` | 고객사명 · 요구사항 번호 · 금액 · 담당자 · 사내 경로 | 금칙어 검사와 치환이 보장하는 것만 |
| `verbatim` | 없음 | 원문 전송이 등급의 정의다 |

`validator.excluded_categories()` 의 docstring 이 원래부터 "확인하지 않은 것을 없다고
쓰면 미리보기가 거짓이 된다"고 적고 있었다. **코드가 자기 계약을 어기고 있었다.**

### 6.4 남기기로 결정한 것

덤프에 `KNOWN_RESIDUALS` 로 근거와 함께 기록했다. 적어두지 않으면 다음 사람이 같은
것을 결함으로 다시 조사하고, 적어두면 그 판단을 남이 반박할 수 있다.

| 무엇 | 판단 |
|---|---|
| `SDK v3.2` (사내 발췌) | 산문 속 제품 버전 표기. `sdk-core` 같은 패키지명은 치환된다. 치환하면 무엇에 대한 질문인지 알 수 없어 답이 무너진다. **미리보기가 이제 이것을 약속하지 않는다** |
| `configs/v3.yaml`, `runs/` | 문서 본문이 언급하는 상대 경로. 저장소 구조가 아니고 접근 경로도 아니다 |
| 컬럼명 | 사내 등급의 정의가 "식별자만 치환하고 기술 내용은 남긴다". 이 값이 비밀이면 그 문서는 애초에 기밀이어야 한다 |

## 7. 그 밖에 찾아 고친 결함

### 7.1 422 응답이 요청 본문을 되비췄다

FastAPI 기본 `RequestValidationError` 핸들러는 오류마다 `input` 을 담는다.
업로드가 상한을 넘겼을 때 **방금 올린 기밀 문서 전문(최대 200,000자)이 오류 응답에
실렸다.**

요청자 자신에게 돌아가므로 유출은 아니다. 그러나

- 오류 응답이 원문을 담는 습관이 생기면 로그·프록시·브라우저 히스토리에 원문이 퍼진다
- 응답 크기가 요청 크기에 비례해 커진다
- 이 프로젝트의 오류 계약(`error` + `correlation_id`)이 깨져 화면이 오류를 표시하지 못한다

`_field_summary()` 로 **필드 이름과 사유만** 남기고 값은 버린다.

### 7.2 재녹화가 게이트를 조용히 뒤집었다

`FixtureStore.save()` 가 무조건 덮어썼다. 재녹화 한 번에 이런 일이 났다.

```
classify_f0c464f5d54d.json
- "tier": "secret"     ← G2(기밀 재현율 100%)를 통과시킨 값
+ "tier": "internal"   ← 같은 입력, 다른 실행
```

같은 프롬프트에 모델이 다른 답을 준 것이다. 키는 **입력**에서 유도되므로 바뀌지 않고,
그래서 `git diff` 에 한 줄로만 나타난다. 놓치기 쉽다.

픽스처의 목적은 "그때 모델이 이렇게 답했다"를 **고정**하는 것이다. 재녹화가 그 고정을
깨면 목업 모드가 재현 가능하지 않게 되고, 오프라인 데모와 게이트가 실행마다 달라진다.

이제 **빠진 것만 채운다.** 갱신은 파일을 지우거나 `MESH_FIXTURE_OVERWRITE=1` 로
명시해야 한다 — 둘 다 의도적인 행위이고 `git status` 에 남는다.

### 7.3 NUL 바이트가 `ValueError` 로 새어 나갔다

속성 테스트(PB-S1)가 찾았다. `os.path.realpath("\x00")` 는
`ValueError: embedded null byte` 를 낸다 — `PathEscapeError` 가 아니다.

`safe_resolve()` 의 계약은 "탈출 시도는 `PathEscapeError`" 이고 호출자는 그 예외만
처리한다. `ValueError` 가 새어 나가면 업로드 경로에서 500 이 되고 감사 로그에 남지 않는다.

### 7.4 시드 데이터가 데모마다 더러워졌다

| 증상 | 고친 방법 |
|---|---|
| 세션 JSON 에서 줄바꿈이 사라져 매 실행 `git diff` 잡음 | `store._write_json()` 이 줄바꿈을 붙인다 |
| `data/corpus/*/uploads/` 가 커밋 대상이 됐다 | `.gitignore` 에 추가 — **사용자 데이터는 소스가 아니다.** 커밋하면 남의 기밀 문서가 저장소 역사에 영구히 남는다 |
| 테스트가 남의 업로드 파일에 의존해 깨졌다 | `conftest.full_data_root` 가 `uploads` 를 복사하지 않는다 |
| 실측 스크립트가 실패하면 파일이 남았다 | `finally` 로 항상 삭제. 세션의 죽은 참조도 함께 정리된다 |

세 번째가 실제로 테스트를 깨뜨렸다. **저장소 상태에 따라 내용이 달라지는 디렉터리를
복사하는 픽스처는 hermetic 하지 않다.**

### 7.5 `make run` 이 깨져 있었다

`uvicorn mesh.main:app` 을 가리켰지만 모듈 수준 `app` 은 존재하지 않는다.
`--factory mesh.main:create_app` 으로 고쳤다.

모듈 수준 `app` 을 두지 않는 이유: import 시점에 `Config.load()` 가 돌아 테스트가
환경변수에 묶인다.

### 7.6 실측 스크립트를 bash 에서 Python 으로

`e2e_upload_ask.sh` 는 bash 안에 Python heredoc 이 5개 있었다. 인용 사고가 잦고,
HTTP 오류가 나면 **원시 traceback** 만 보였다 (`HTTP Error 400: Bad Request` — 본문 없음).

`e2e_upload_ask.py` 로 다시 썼다.

- 오류 응답 본문(`error` + `detail` + `correlation_id`)을 함께 보여준다
- 시작 시 `/api/health` 로 모드를 확인하고 목업이면 **즉시** 멈춘다 —
  매번 새 문서를 만들므로 픽스처가 있을 수 없다
- 7단계로 나누어 각 단계의 판정을 출력한다

## 10. 이번에 다시 확인한 것

**검사기를 검사하지 않으면 검사기가 조용히 아무것도 안 한다.**
`lint_web.py` 가 두 번 그랬고, `sweep_for_leaks` 는 목록에 없는 것을 못 봤고,
`excluded_categories` 는 자기 docstring 을 어겼다.

세 경우 모두 **"통과"를 출력했다.** 그래서 G4 가 사람의 눈을 요구하고,
`test_lint_web.py` 가 검사기 자체를 검사하고, 덤프에 판단 근거를 적어 둔다.

자동 검사는 회귀를 막고, 사람은 **처음 보는 것**을 찾는다. 둘은 대체 관계가 아니다.
