# U4 — Business Rules

규칙 ID: `BR-U-*`

---

## BR-U-01 · 페이로드는 전문을 보여준다 (FR-41) 🔴

미리보기 모달에서 **생략·접기·"더 보기"를 쓰지 않는다.**

- `...` 축약 금지
- `<details>` 접기 금지
- 최대 높이 제한 후 스크롤 금지 (2KB 제한이 스크롤 없이 읽히게 보장한다)

**근거**: 이게 4번째 방어 겹이다 (설계 §3.5). 심사자가 전량을 읽어야 성립한다. 일부만 보이면 "나머지에 무엇이 있는지 모른다"가 되고, 방어 겹 하나가 사라진다.

---

## BR-U-02 · 없는 것을 보여준다

`excluded_categories`("포함되지 않은 것")를 모달에 명시한다.

```
포함되지 않은 것
  고객사명 · 제품명 · 버전 · 요구사항 번호 · 원문 문장 · 담당자 · 일정 · 금액
```

**있는 것을 보여주는 것보다 없는 것을 보여주는 게 설득력이 있다.** JSON을 읽고 "고객사명이 없네"를 스스로 확인하는 것과, 목록으로 "여기엔 이것들이 없습니다"를 읽고 JSON에서 확인하는 것은 인지 비용이 다르다.

`verbatim_sentence_count`도 **측정값으로** 표시한다. "원문 0개"가 주장이 아니라 계산 결과가 된다.

## BR-U-03 · 취소는 아무것도 남기지 않는다 (FR-09)

`[취소]`를 누르면 `send`를 호출하지 않는다. 서버가 감사 레코드를 남기지 않는다.
클라이언트는 `envelope_id`를 버리고 캐시는 TTL로 소멸한다.

**검증**: 취소 후 감사 로그 탭에 레코드가 없음을 확인하는 예제 테스트.

---

## BR-U-04 · 2명 지목 시 순차 승인

두 대상의 페이로드가 다르므로 모달을 **하나씩** 띄운다.
사용자가 하나만 승인하고 나머지를 취소할 수 있다 — 그 경우 승인한 쪽만 답이 온다.

한 모달에 두 페이로드를 합쳐 보여주지 않는다. 등급이 다를 수 있고, "한 번의 승인에 한 등급"이 BR-G-08과 짝을 이룬다.

---

## BR-U-05 · 인용에 경로를 표시하지 않는다 (FR-43) 🔴

`display_title` + `section` + `tier` + `as_of` + `formality`만 렌더한다.

**`internal_path`는 API 응답에 없으므로 표시할 방법이 없다.** 서버가 구조적으로 보장한다.
UI 코드에 `internal_path`가 등장하면 안 되고, 등장할 수도 없다.

**검증**: `grep -c "internal_path" src/mesh/web/app.js` == 0

## BR-U-06 · 사람인 척하지 않는다 (FR-26)

모든 답변에 `"○○의 Agent"` 라벨을 표시한다. 사람 이름만 표시하는 경로가 없다.

> 사람인 줄 알았다가 아니었다는 경험은 신뢰를 단번에 무너뜨린다.

## BR-U-07 · 상충을 단정하지 않는다 (FR-33, Round 2 Q11)

| 금지 문구 | 사용 문구 |
|---|---|
| "엇갈립니다" | "서로 다릅니다" |
| "충돌합니다" (병기 헤더) | "판단에 참고하세요" |
| — | "둘 다 사실일 수 있습니다. 시점이 {gap} 차이이고 문서 성격이 다릅니다." |

`divergence_note`는 서버가 만든 고정 템플릿을 그대로 표시한다. UI가 문구를 만들지 않는다.

**신뢰도 높은 쪽을 강조하거나 위에 배치하지 않는다.** `targets` 요청 순서대로 표시한다 (BR-O-07).

## BR-U-08 · `null`은 표시하지 않는다

`AgentCard`의 `disclose`가 꺼진 필드는 `null`로 온다. 이때:

- "정보 없음"·"비공개"·"—" 같은 표시를 하지 **않는다**
- 해당 행·요소를 **아예 렌더하지 않는다**

**"비공개"라고 표시하면 그 자체가 정보다.** "이 사람은 상태를 숨기고 있다"를 알려주는 것이고, 그건 `disclose: false`의 의도가 아니다.

---

## BR-U-09 · 목업 모드와 경계 시뮬레이션을 숨기지 않는다 (FR-48, Round 2 Q15) 🔴

| 상태 | 표시 |
|---|---|
| `health.exaone_mode == "mock"` | 헤더에 **주황 `MOCK` 배지 + "목업 모드"** |
| `health.agent_transport == "mock"` | 동일 |
| `health.trust_boundary_simulated == true` | 헤더에 **"경계 시뮬레이션"** + 클릭 시 설명 팝오버 |

**숨기면 심사자를 속이는 것이다.** 데모의 신뢰성이 프로젝트의 유일한 자산이므로 여기서 양보하지 않는다.

경계 고지 팝오버 문구는 서버가 아니라 UI에 고정 문구로 둔다 (설명이 길고 자주 바뀌지 않는다).

## BR-U-10 · 0건을 크게 표시한다 (FR-42) 🔴

감사 로그 검색 결과가 0건일 때:

```
╔════════════════════════════════════════════════════════════════╗
║  0건 — 이 문구는 경계를 넘은 적이 없습니다                     ║
╚════════════════════════════════════════════════════════════════╝
```

- 검색어가 있고 결과가 0건일 때만 표시 (검색 전에는 표시하지 않는다)
- `aria-live="assertive"`로 스크린 리더에 알린다
- 작은 "결과 없음" 텍스트로 처리하지 않는다 — **이게 1막의 결정적 장면이다**

데모용 빠른 검색 버튼(`REQ-4412`, `EAP-AKA`, `H社`, `12억`)을 둔다. 시연 중 타이핑 실수로 흐름이 끊기는 것을 막는다.

## BR-U-11 · 신뢰 구역 내 처리를 감사 로그에 섞지 않는다 (BR-A-03)

`GET /api/audit`는 `audit` 테이블만 반환한다 (`local_queries` 제외).

**"레코드가 없다"가 증거가 되려면 섞이면 안 된다.** 시나리오 3에서 폴백 질의가 감사 로그에 보이면 "나갔나 안 나갔나"가 흐려진다.

---

## BR-U-12 · CSP를 우회하지 않는다 (NFR-S-04)

`Content-Security-Policy: default-src 'self'`이고 `unsafe-inline`이 없다. 따라서:

| 금지 | 대체 |
|---|---|
| 인라인 `<script>` | `app.js` |
| 인라인 `<style>` | `style.css` |
| `onclick="..."` 속성 | `addEventListener` |
| `eval` / `new Function` | 사용 안 함 |
| `element.innerHTML = userText` | `textContent` 또는 명시적 escape |
| 외부 CDN (폰트·아이콘·JS) | 시스템 폰트 + 유니코드 문자 + 로컬 파일 |

**외부 CDN을 쓰지 않으므로 SRI가 N/A다** (SECURITY-13). 폰트는 `system-ui, -apple-system, sans-serif`, 아이콘은 유니코드(`🟢 ⚪ 📄 ⚠️`)를 쓴다.

**`innerHTML` 금지가 XSS 방어다.** 답변 텍스트·인용 제목·페이로드 JSON이 모두 `textContent`로 들어간다. JSON 하이라이팅도 DOM 노드를 만들어 붙인다 (문자열 조립 금지).

## BR-U-13 · 색상 단독 금지

등급·신뢰도·처분 배지는 색상과 **텍스트 라벨을 병기**한다.

```
✅ [기밀]  (빨강 배경 + "기밀" 텍스트)
❌ 빨강 점만
```

**보안 UI에서 색각 이상 사용자가 기밀과 공개를 구별할 수 없으면 기능 결함이다.** 접근성 이전에 정확성 문제다.

대비 4.5:1 이상.

---

## BR-U-14 · 로딩 중 중복 전송 방지

`state.busy`가 `true`면 전송 버튼을 비활성화한다.
`send`는 서버에서도 일회용(`take()`)이지만, 클라이언트에서도 막아 사용자 혼란을 줄인다.

`aria-live="polite"` 영역에 "Agent에게 질문 중..." 표시.

---

## BR-U-15 · 사용자 전환은 인증이 아니다

드롭다운 사용자 전환에 인증이 없다. 이건 **MVP의 명시적 한계**다 (요구사항 §7).

UI에 이 사실을 표시한다:
```
사용자: 최민수 선임 v    (데모용 전환 · 인증 없음)
```

실배포에서는 원본 시스템 권한 승계가 전제라는 것을 `README`와 이 표시로 남긴다.
숨기면 심사자가 "권한 관리는 어떻게 되나요"라고 물었을 때 약점이 되고, 밝히면 "MVP 범위를 명확히 안다"가 된다.
