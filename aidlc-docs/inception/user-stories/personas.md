# Personas

원천: `requirements/scenarios.md` 3개 시나리오의 등장인물.
샘플 데이터이므로 실제 인물이 아니며, 데모 재현성을 위해 고정한다.

---

## 질문하는 쪽

### P1. 최민수 선임 — 인접 담당자 (시나리오 1 질문자 / 시나리오 3 응답자)

| | |
|---|---|
| **역할** | SDK 인증 모듈 담당, 배포 파이프라인 |
| **상황** | 고객사 협의에는 참여하지 않는다. 고객사 요구사항명세서를 **볼 권한도, 읽을 시간도 없다** |
| **핵심 욕구** | 내가 못 보는 문서에 대한 판단을 얻고 싶다. 김책임을 30분 붙잡지 않고 |
| **좌절 지점** | 지금까지라면 물어보고 30분 대기 |
| **이 시스템에서** | 김책임 Agent에 묻고, 나갈 페이로드를 직접 눈으로 확인하고 승인한다 |
| **주의** | 인용에 문서명은 보이지만 **경로·본문은 보이지 않아야 한다** (권한 관리 없는 MVP의 경계선) |

### P2. 정연구원 — 다른 팀 협업자 (시나리오 2 질문자)

| | |
|---|---|
| **역할** | 다른 팀 연구원. 같은 데이터로 실험을 하나 돌려보려 한다 |
| **핵심 욕구** | (1) 기법을 알고 싶다 (2) 지금 스크립트를 돌려도 되는지 허락받고 싶다 |
| **좌절 지점** | **이 질문의 답은 어떤 문서에도 없다.** 위키에도 Jira에도 없고, 절반은 *지금 이 순간의 상태*다 |
| **이 시스템에서** | 질문이 2개로 분해된다. 기법은 Agent가 자동 응답, 허락은 사람에게 에스컬레이션 |
| **주의** | 두 하위 질문의 등급이 갈리면 **호출을 나눈다** |

### P3. 한지원 — 입사 3주차 (시나리오 3 질문자)

| | |
|---|---|
| **역할** | 신입. 인증 모듈 코드를 읽다 막혔다 |
| **핵심 욕구** | "왜 이렇게 설계됐는지"를 알고 싶다. 커밋 로그의 두 이름 중 누가 맞는지 모른다 |
| **좌절 지점** | **물어볼 곳이 가장 많고, 시니어를 방해하기는 가장 미안한 사람** |
| **이 시스템에서** | 둘 다 지목한다. 답이 갈리면 병기된 것을 보고 스스로 판단한다 |
| **왜 중요한가** | **온보딩이 이 시스템의 가장 자연스러운 진입점이다.** 질문량이 가장 많다 |

## 대리되는 쪽 (에이전트 소유자)

### P4. 김철수 책임 — 지식 보유자 (시나리오 1·3 응답자)

| | |
|---|---|
| **역할** | 인증 · SSO · SDK 보안. 고객사 H 협의 담당, 인증 아키텍처 설계자 |
| **세션 상태** | 🟢 활동 중 · 고객사 H 인증 요구사항 검토 + SDK v3.2 토큰 정책 |
| **핵심 욕구** | **방해받지 않고 싶다.** 같은 질문에 반복해서 답하고 싶지 않다 |
| **좌절 지점** | 메신저 알림 → 작업 중단 → 상황 파악 → 설명 → 재집중. 매번 20분 |
| **이 시스템에서** | 시나리오 1에서 **이 대화를 알지도 못한다.** 답할 수 없을 때만 요약·근거·초안이 붙어 도달한다 |
| **자료 특성** | 설계 문서 6, 회의록 4, 개인 메모 4. **결정의 근거는 개인 메모에 반쪽짜리로 남아 있다** |

### P5. 박선영 선임 — 실시간 상태 보유자 (시나리오 2 응답자)

| | |
|---|---|
| **역할** | 데이터 파이프라인 · 모델 학습 |
| **세션 상태** | 🟢 활동 중 · 지금 학습 실행 중 (14:02 시작, 17:10 예상, `cuda:0` 점유) |
| **핵심 욕구** | 기법 질문은 대신 답해 주고, **판단이 필요한 것만** 나에게 오게 하고 싶다 |
| **이 시스템에서** | 인박스에 초안이 준비돼 있고 `[수정 후 승인]`으로 **25초에 종결** |
| **왜 중요한가** | 그의 지식 절반은 **문서가 아니라 현재 상태**다. 어떤 인덱스도 이걸 못 담는다 |

## 검증하는 쪽

### P6. 보안 검토자 / 해커톤 심사자

| | |
|---|---|
| **핵심 질문** | "정말 원문이 안 나갔는가? 증명해 보라" · "그냥 EXAONE만 쓰면 되지 않나?" |
| **필요한 것** | (1) 나갈 내용 전문을 **3초에 읽을 수 있는 형태** (2) 감사 로그에서 원문 문구 검색 → 0건 (3) EXAONE 단독 대비 품질 우위 |
| **설득되는 방식** | 주장이 아니라 **검증 결과.** 샘플 데이터라 전수 검사가 가능하다는 점이 핵심 |
| **경계할 것** | 신뢰 경계가 시뮬레이션이라는 점을 **먼저 밝히지 않으면** 지적당했을 때 주장 전체가 무너진다 |
