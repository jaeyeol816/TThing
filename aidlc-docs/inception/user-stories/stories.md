# User Stories

우선순위: **P0** = 없으면 데모가 성립하지 않음 · **P1** = 있어야 주장이 완성됨 · **P2** = 있으면 좋음
`FR-*`는 `aidlc-docs/inception/requirements/requirements.md` 참조.

## Epic A — 기밀 자료에 외부 AI를 쓴다 (시나리오 1 · 프로젝트의 핵심)

### S-01 · 나갈 내용을 눈으로 확인하고 승인한다 · P0
**As** 최민수 선임 (P1)
**I want** Agent에게 전송될 페이로드 전문을 전송 전에 보고 승인/취소하고 싶다
**So that** 내가 못 보는 문서에 대해서도 무엇이 외부로 나가는지 내가 판단할 수 있다

**Acceptance Criteria**
- [ ] 모달에 페이로드 JSON **전문**이 표시된다 (일부 생략 없이)
- [ ] 등급 배지, 바이트 크기, 검증 통과 단계 수(`6/6`)가 함께 표시된다
- [ ] **"포함되지 않은 것"** 목록이 명시된다 (고객사명·제품명·요구사항 번호·원문)
- [ ] `[전송]`을 누르지 않으면 Agent 호출이 발생하지 않는다 — 취소 시 감사 로그에 레코드가 남지 않는다
- [ ] 페이로드가 2KB 이하라 화면 스크롤 없이 읽힌다
- FR-09, FR-41

### S-02 · 기밀 문서를 자동으로 최고 등급으로 판정받는다 · P0
**As** 시스템 사용자
**I want** 기밀 문서가 예외 없이 기밀로 분류되기를 원한다
**So that** 등급을 낮게 잡은 실수(=유출)가 일어나지 않는다

**Acceptance Criteria**
- [ ] 규칙 기반(경로 `customer-*/**`, 헤더 등급 표기, 고객사명 사전, 계약번호 정규식)과 EXAONE 판정 중 **높은 쪽**을 채택
- [ ] `labels.json` 기준 **기밀 재현율 100%** — 하나라도 놓치면 실패
- [ ] 전체 등급 분류 정확도 ≥ 90%
- [ ] **함정 문서**(겉보기엔 일반 설계 문서인데 고객사 단가 포함)를 기밀로 잡는다
- [ ] 판정 실패·타임아웃 시 `secret`으로 간주한다
- FR-01, FR-02, FR-52

### S-03 · 원문 문장 0개로 유용한 답을 받는다 · P0
**As** 최민수 선임 (P1)
**I want** 기밀 문서를 근거로 한 실질적인 답변(충돌 여부 + 완화안)을 받고 싶다
**So that** 기밀이라는 이유로 AI의 도움을 포기하지 않는다

**Acceptance Criteria**
- [ ] Agent에게 가는 페이로드에 원문 문장이 0개
- [ ] 그런데도 답변에 충돌 여부(`bool`), 이유(`string`), 완화안(`string[]`)이 담긴다
- [ ] 페이로드는 **코드가 조립한다** — 스키마 슬롯 밖의 키는 조립 단계에서 버려진다
- [ ] 어휘 사전 밖의 값은 만들어지지 않는다
- FR-03, FR-04

### S-04 · 답변을 실제 이름으로 자연스럽게 읽는다 · P0
**As** 최민수 선임 (P1)
**I want** `REQ_A` 같은 기호가 아니라 `고객사 H REQ-4412`로 된 답변을 보고 싶다
**So that** 보안을 위해 가독성을 희생하지 않는다

**Acceptance Criteria**
- [ ] Agent 응답의 모든 `ref`가 실제 이름으로 치환된다
- [ ] 치환은 **신뢰 구역 안에서** 순수 문자열 치환으로 이뤄진다
- [ ] 매핑 테이블은 앱 메모리에만 존재하고 **응답 후 폐기**된다 (파일·DB·클라우드에 남지 않는다)
- [ ] 가명화 → 재수화 왕복이 항등임을 속성 테스트로 증명 (PBT-02)
- FR-13, NFR-T-02

### S-05 · 유출 0건을 검색으로 증명한다 · P0
**As** 보안 검토자 (P6)
**I want** 원문의 아무 문구나 골라 감사 로그를 검색해 0건임을 확인하고 싶다
**So that** "유출 없음"이 주장이 아니라 검증 결과가 된다

**Acceptance Criteria**
- [ ] 감사 로그 탭에서 임의 문자열 검색이 가능하다
- [ ] `REQ-4412`, `EAP-AKA`, `H社` 검색 → **각 0건**
- [ ] 경계 밖으로 나간 페이로드가 **전량** 보관돼 있다 (승인된 것만, 취소된 것은 레코드 없음)
- [ ] 자동 전수 검사(`make eval`)가 기밀·사내 문서의 모든 5-gram을 전 페이로드와 대조해 0건임을 확인
- FR-15, FR-42, FR-55

### S-06 · 질문 문장 자체도 검사받는다 · P0
**As** 시스템 사용자
**I want** 내 질문에 고객사명이나 요구사항 번호가 섞여 있으면 그것도 변환되기를 원한다
**So that** 지식만 막고 질문이 그대로 새는 구멍이 없다

**Acceptance Criteria**
- [ ] 질문 문자열도 등급 판정과 변환(관문 ①)을 거친다
- [ ] 고객사명이 포함된 질문으로 테스트했을 때 페이로드에 해당 문자열이 없다
- FR-10

### S-07 · 동원된 지식이 기밀이면 호출 전체가 기밀이 된다 · P0
**As** 시스템 사용자
**I want** 질문이 사내 등급이어도 읽은 파일에 기밀이 있으면 전체가 기밀로 처리되기를 원한다
**So that** 등급이 질문 단위로 잘못 매겨져 원문이 나가지 않는다

**Acceptance Criteria**
- [ ] `tier = max(질문 등급, 동원된 모든 파일의 등급)`
- [ ] 시나리오 1에서 질문은 `internal`, 파일 중 하나가 `secret` → 호출 전체가 `secret`
- [ ] `AgentCall.tier`는 단일값이며, 등급이 섞인 페이로드는 조립되지 않는다
- FR-11, FR-12

### S-08 · 외부 추론의 실익을 확인한다 · P1
**As** 보안 검토자 (P6)
**I want** 같은 질문을 EXAONE 단독으로 처리한 결과와 비교하고 싶다
**So that** "그냥 EXAONE만 쓰면 되지 않나"에 답할 수 있다

**Acceptance Criteria**
- [ ] 동일 질문에 대해 두 경로(EXAONE 단독 / 구조추출+Agent)의 답변을 나란히 볼 수 있다
- [ ] 비교 결과가 평가 리포트에 기록된다
- FR-55

## Epic B — 사람 대신 답하고, 못 하면 다듬어서 넘긴다 (시나리오 2)

### S-09 · 아는 사람을 직접 지목한다 · P0
**As** 정연구원 (P2)
**I want** 에이전트 목록에서 대상을 직접 고르고 싶다
**So that** 시스템의 오라우팅에 맡기지 않고 정확하게 묻는다

**Acceptance Criteria**
- [ ] 목록에 담당 영역(본인 작성)이 항상 표시된다
- [ ] 활동 상태·오늘 질문 수·현재 작업 요약은 **에이전트별 opt-in**으로 켜고 끌 수 있다
- [ ] 최대 2명까지 선택 가능
- [ ] 전문성 매칭·임베딩·브로드캐스트 로직이 **코드에 존재하지 않는다**
- FR-29, FR-30, FR-32

### S-10 · 목록 표시가 기밀을 새게 하지 않는다 · P0
**As** 김철수 책임 (P4)
**I want** "지금 인증 관련 작업 중"까지만 공개되고 고객사명이 노출되지 않기를 원한다
**So that** 인증 없이 보이는 목록 화면이 게이트키퍼 우회 경로가 되지 않는다

**Acceptance Criteria**
- [ ] `current_focus`는 세션 `focus` 원문이 아니라 **식별자 제거 요약**이다
- [ ] 이 변환도 게이트키퍼를 통과한다
- [ ] 목록 API 응답에 고객사명·경로가 없다
- FR-31

### S-11 · 방해받지 않는다 · P0
**As** 김철수 책임 (P4)
**I want** 내 Agent가 답할 수 있는 질문에 대해 나에게 알림이 오지 않기를 원한다
**So that** 하던 일이 끊기지 않는다

**Acceptance Criteria**
- [ ] 자동 응답으로 종결된 질의는 담당자 인박스에 들어가지 않는다
- [ ] 방지된 인터럽트 건수와 절감 추정 시간이 카운터로 표시된다
- FR-34, FR-44

### S-12 · 문서에 없는 지식을 답받는다 · P0
**As** 정연구원 (P2)
**I want** 개인 스크립트·설정 파일에만 있는 기법을 답받고 싶다
**So that** 위키 검색으로는 못 찾는 것을 얻는다

**Acceptance Criteria**
- [ ] 세션의 `open_paths` 중에서 관련 파일을 골라 읽는다 (전역 검색 없음)
- [ ] 답변에 구체적 파라미터(`sampling_strategy=0.5`, `class_weight='balanced_subsample'`)가 담긴다
- [ ] 인용에 파일명과 최종 수정 시각이 표시된다
- FR-16, FR-17

### S-13 · 사내 등급은 논리를 살려 가명화한다 · P0
**As** 정연구원 (P2)
**I want** 사내 문서에 대해서는 구체적인 답변을 받고 싶다
**So that** 기밀이 아닌 것까지 무디게 처리되지 않는다

**Acceptance Criteria**
- [ ] 사내 프로젝트명·경로만 placeholder로 치환된다 (`atlas_ml` → `<PROJ_1>`)
- [ ] **기술 용어는 치환하지 않는다** (`RandomOverSampler`, `balanced_subsample` 그대로)
- [ ] placeholder가 한 질의 안에서 일관된다 (같은 대상 = 같은 번호)
- FR-05, FR-06

### S-14 · 지금 무슨 일이 벌어지는지 답받는다 · P0
**As** 정연구원 (P2)
**I want** "박선임이 지금 그 스크립트를 돌리고 있다"를 알고 싶다
**So that** GPU 충돌을 미리 피한다

**Acceptance Criteria**
- [ ] 세션의 `recent_runs`가 답변 근거로 사용된다
- [ ] 답변에 실행 시작 시각·완료 예상·점유 GPU가 담긴다
- [ ] 근거에 **세션 기준 시각**이 표시된다 (`🔴 세션 · 14:33 기준`)
- FR-16, FR-19

### S-15 · 등급이 갈리는 질문이 분해된다 · P1
**As** 정연구원 (P2)
**I want** 기법 질문과 허락 질문이 각각 적절히 처리되기를 원한다
**So that** 하나가 기밀이라고 전부가 무뎌지지 않는다

**Acceptance Criteria**
- [ ] 질문이 하위 질문으로 분해되고 각각 등급이 매겨진다
- [ ] 분해 조건: 자기 `answer_format`을 갖고, `needs[]`가 겹치지 않고, 조각만으로 값이 있을 때
- [ ] 조건에 어긋나면 분해하지 않고 `max(tier)`로 상향
- [ ] 한 번의 Agent 호출에는 **한 등급만** 담긴다
- FR-12

### S-16 · 초안이 준비된 인박스로 25초에 끝낸다 · P0
**As** 박선영 선임 (P5)
**I want** 질문 요약 + 근거 + 답변 초안이 준비된 상태로 받고 싶다
**So that** 처리 비용이 20분에서 몇 초로 떨어진다

**Acceptance Criteria**
- [ ] 인박스 항목에 **요약 / 상황(근거) / 초안**이 모두 있다
- [ ] `[승인] [수정 후 승인] [내가 아님]` 3버튼
- [ ] `[수정 후 승인]`에서 한 줄 덧붙여 승인할 수 있다
- [ ] 승인 후 질문자 화면에 답변이 반영된다
- FR-27, FR-38

### S-17 · 승인된 답변이 환류된다 · P1
**As** 박선영 선임 (P5)
**I want** 승인한 답변이 저장돼 같은 질문이 두 번 오지 않기를 원한다
**So that** 같은 설명을 반복하지 않는다

**Acceptance Criteria**
- [ ] `data/verified/{entity_id}.json`에 영속 저장 (세션과 별도)
- [ ] 세션 로드 시 병합된다
- [ ] **등급을 함께 보존**하고, 이후 동원될 때 다른 지식과 똑같이 게이트키퍼를 통과한다
- [ ] 같은 질문 재요청 시 사람 없이 자동 응답
- FR-20

### S-18 · 잘못 물었으면 사람이 되돌린다 · P1
**As** 김철수 책임 (P4)
**I want** 내 담당이 아니면 다른 사람을 지목해 되돌리고 싶다
**So that** 알고리즘 추정보다 정확하게 라우팅된다

**Acceptance Criteria**
- [ ] `[내가 아님]` 선택 시 대상 지목 UI가 뜬다
- [ ] 질문자 화면에 "○○이 △△를 지목했습니다 `[다시 묻기]`"
- [ ] 시스템이 자동 재지목하지 않는다
- FR-39

## Epic C — 기억이 엇갈릴 때, 그리고 막힐 때 (시나리오 3)

### S-19 · 자리에 없는 사람의 에이전트도 답한다 · P0
**As** 한지원 (P3)
**I want** 최민수가 2시간째 부재중이어도 그의 Agent가 답하기를 원한다
**So that** "물어볼 사람이 자리에 없다"가 대기 사유가 되지 않는다

**Acceptance Criteria**
- [ ] 세션이 마지막 상태로 정지해 있어도 파일은 읽힌다
- [ ] 목록에 `⚪ 자리 비움 (2시간)`이 표시된다
- [ ] 답변에 세션 기준 시각이 명시된다
- FR-18, FR-19

### S-20 · 갈리는 답을 병기해서 본다 · P0
**As** 한지원 (P3)
**I want** 두 사람의 답이 다를 때 양쪽을 다 보고 싶다
**So that** 하나가 조용히 묻히지 않는다

**Acceptance Criteria**
- [ ] 2명 지목 시 병렬 호출하고 답을 **병기**한다
- [ ] `divergent: true`로 표시하되 **상충 여부를 자동 판정하지 않는다**
- [ ] 각 답에 `as_of`(근거 시점)와 `formality`(공식/비공식)가 표시된다
- [ ] 문구는 "엇갈립니다"라는 단정이 아니라 "둘 다 사실일 수 있습니다"
- [ ] `[두 분께 확인 요청]`이 같은 스레드로 두 인박스에 들어간다
- FR-32, FR-33

### S-21 · 어휘 사전에 없는 것은 실수로도 못 나간다 · P0
**As** 보안 검토자 (P6)
**I want** 어휘 사전에 없는 필드가 생성되면 전송이 차단되기를 원한다
**So that** 화이트리스트 방식의 실효성이 증명된다

**Acceptance Criteria**
- [ ] 성능 수치 필드(`p99_latency_ms`, `throughput_tps`)가 `vocab.json`에 **의도적으로 없다**
- [ ] EXAONE이 그 필드를 만들려 하면 조립 단계에서 버려지고, 슬롯이 다 비면 전송하지 않는다
- [ ] Agent를 호출하지 않고 EXAONE이 신뢰 구역 안에서 직접 답한다
- [ ] 답변에 `[기밀 · 사내망 밖으로 나간 것 없음]` 표시
- [ ] **감사 로그에 이 질의 레코드가 없다** (경계를 넘은 것이 없으므로)
- FR-07, FR-08, FR-54

### S-22 · 근거 없는 답은 도달하지 않는다 · P0
**As** 시스템 사용자
**I want** 인용이 0개인 답변은 자동 응답되지 않기를 원한다
**So that** 환각이 사용자에게 도달하지 않는다

**Acceptance Criteria**
- [ ] 인용 0개 → 신뢰도와 무관하게 에스컬레이션
- [ ] 자동 응답 중 인용 1개 이상 비율이 **100%** (구조적 보장)
