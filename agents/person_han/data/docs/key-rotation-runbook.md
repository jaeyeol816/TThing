# 서명 키 회전 런북

## 1. 원칙

회전 중에도 **이전 키로 서명된 토큰이 검증돼야 한다.** 그래서 키는 언제나
두 개가 살아 있다 (current / previous).

## 2. 절차

1. 새 키 생성 → JWKS 에 **추가만** 한다 (기존 키 유지)
2. JWKS 전파 대기 — 최소 액세스 토큰 수명(15분)의 2배
3. 서명 키를 새 키로 전환 (`current` 교체)
4. 이전 키 유지 — 리프레시 토큰 수명이 지날 때까지
5. 이전 키 제거

3번과 5번 사이를 줄이려는 시도를 반복적으로 하게 되는데, **줄이면 안 된다.**
줄이면 아직 살아 있는 토큰이 검증에 실패한다.

## 3. 수동 절차의 문제

지금까지 1~5 를 사람이 했다. 실패 사례가 두 종류 있었다.

- 2번 대기를 건너뜀 → 전파 전 전환으로 검증 실패
- 5번을 잊음 → 폐기했어야 할 키가 JWKS 에 남음

둘 다 "사람이 기억해야 하는 것"이 원인이다. 그래서 CI 작업으로 옮긴다.

## 4. 자동화 후 남는 수동 확인

- 무중단 확인: 회전 전후로 기존 토큰 검증이 계속 성공하는지
- 이 확인만은 자동화하지 않는다. 자동화하면 검증 로직의 버그를 검증 로직이
  검사하는 셈이 된다.
