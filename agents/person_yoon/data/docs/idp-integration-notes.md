# 외부 IdP 연동 검증 노트

## 1. 대상 규격

OIDC Core 1.0 + Back-Channel Logout 1.0. SAML 2.0 은 기존 연동 유지 목적으로만
남기고 신규 연동에는 쓰지 않는다.

## 2. 백채널 로그아웃으로 바꾸는 이유

프런트채널 로그아웃은 브라우저가 살아 있어야 전파된다. 모바일 SDK 에서는
그 전제가 성립하지 않아 **로그아웃했는데 토큰이 살아 있는** 구간이 생긴다.

백채널은 IdP 가 서버로 직접 알린다. 브라우저와 무관하다.

## 3. 토큰 수명 정책과의 상호작용

로그아웃 전파가 즉시라도, 이미 발급된 액세스 토큰은 만료까지 유효하다.
전파 지연의 상한은 결국 **액세스 토큰 수명**이다.

    실질 무효화 지연  =  전파 지연  +  잔여 액세스 토큰 수명

전파를 아무리 빠르게 만들어도 두 번째 항이 남는다. 그래서 토큰 수명 정책을
같이 보지 않으면 이 작업은 절반만 하는 것이 된다.

## 4. 표준이 허용하는 것 vs 우리 구현이 하는 것

| 항목 | 표준 | 우리 구현 |
|---|---|---|
| 로그아웃 토큰 검증 | 서명·aud·iss·jti 필수 | 동일 |
| jti 재사용 방지 | 권장 | **미구현** — 검증 항목으로 남아 있음 |
| sid 기반 세션 지정 | 선택 | 사용 (sub 단독 로그아웃은 미지원) |

세 번째 줄이 중요하다. 표준은 sub 만으로도 되지만 우리 구현은 sid 를 요구한다.
연동 상대가 sid 를 안 보내면 로그아웃이 조용히 무시된다.

## 5. 남은 것

- jti 재사용 방지 구현
- sid 누락 시 경고 로그 (현재는 무시)
