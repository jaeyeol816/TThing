# 서빙 부하 테스트 결과 — int8 양자화

**목적**: int8 양자화 적용 전후 지연·처리량·정확도 비교
**환경**: 시험 환경 (스테이징 서버, `configs/serving.yaml`)
**날짜**: 2026-08-18

> ⚠️ 시험 환경 수치. 운영 환경에 직접 적용 전 운영 조건으로 재측정 필요.

---

## 1. 처리량 · 지연 비교

| 시나리오 | p50 지연 | p95 지연 | p99 지연 | 최대 처리량 |
|---|---|---|---|---|
| 기준선 (fp32, batch=1) | 28 ms | 61 ms | 89 ms | 820 req/s |
| int8, batch=1 | 17 ms | 38 ms | 56 ms | 1,340 req/s |
| int8, batch=4 | 9 ms | 22 ms | 31 ms | **3,210 req/s** |
| int8, batch=4 + 오토스케일 | 8 ms | 19 ms | 28 ms | ~12,840 req/s (4 replica) |

**p99 기준 39% 지연 감소**, 처리량 약 4배 (batch=4 기준).

---

## 2. 정확도 회귀

> 이 측정은 배현수 연구원의 검증 셋 기반 비교 **전** 수치다.
> 공식 비교는 배현수가 담당 (08-20 예정).

빠른 자체 측정: inference 결과를 fp32 기준선과 비교.

| 지표 | fp32 | int8 | 차이 |
|---|---|---|---|
| 샘플 1000건 일치율 | — | **99.1%** | — |
| 클래스 1 판정 불일치 | — | 9건 / 1000건 | |

9건 불일치는 확률값이 0.5 경계 근처인 경우였다. 경계 케이스 처리 방식을
배현수 연구원과 논의 필요.

---

## 3. GPU 자원

| 항목 | fp32 | int8 |
|---|---|---|
| VRAM 사용 | 11.2 GB | **6.8 GB** |
| GPU 활용률 (p50) | 68% | 54% |

VRAM 절반 수준. 같은 GPU 에서 replica 2개 운영 가능해진다.

---

## 4. 오토스케일링 파라미터

현재 설정 (`serving.yaml`):
- `target_queue_delay_ms: 15` — 큐 대기 15ms 초과 시 확장
- `max_replicas: 4`

int8 + batch=4 기준, 4 replica 합산 처리량이 약 12,840 req/s.
현재 피크 트래픽 예측치의 **3.2배**. 충분한 여유.
