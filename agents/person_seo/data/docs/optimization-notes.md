# 추론 최적화 검토 노트

## 1. 지금 재고 있는 것

- **int8 양자화**: 부하 테스트 완료 (`benchmarks/load-test-2026-08-18.md`)
- **배치 크기**: batch=1 vs batch=4 비교 완료 (batch=4 가 p99 기준 우세)
- **오토스케일**: target_queue_delay_ms 파라미터 튜닝 중

## 2. 측정 조건 원칙

수치를 말할 때 조건을 반드시 함께 말한다.

| 조건 | 현재 시험 | 운영 예상 |
|---|---|---|
| 환경 | 스테이징 | 운영 클러스터 |
| GPU | A100 (시험) | T4 × 2 (운영) |
| 배치 크기 | 4 | 미정 |
| 연결 방식 | gRPC | REST (운영) |

GPU 모델이 다르다. 시험 수치를 운영에 직접 쓰면 안 된다.

## 3. 아직 안 한 것

- TensorRT 전환 (int8 대비 추가 이점 알 수 없음)
- FP16 절충 (int8 보다 정확도 손실 적을 수 있음)
- 배치 크기 8 이상 (큐 대기 지연 증가 우려)

## 4. 배치 크기 결정 원칙

배치 크기를 늘리면 처리량이 늘고 지연이 늘어난다.
p99 목표가 50ms 이면 batch=4 가 현재 한계다.
목표를 완화하면 처리량을 더 올릴 수 있으나, 그 결정은 내가 하지 않는다.

## 5. 서빙-학습 연동 시 주의

모델이 교체되면 서빙 설정을 같이 검토한다.
양자화를 적용한 모델과 적용 안 한 모델은 같은 설정을 쓸 수 없다 —
VRAM 점유, 배치 처리 시간이 다르다.

지금 학습 중인 `runs/2026-08-19` 모델이 완료되면 서빙 설정 재검토 필요.
